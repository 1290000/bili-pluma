# `--fast` 盲区分析 · 1.2.0 实测归类

> 问题：本轮 4 条 🔴 里，`--fast` 能抓到几条？
> 结论：**0 条全部抓到；3 条完全抓不到，1 条抓到但抓得不全。**
> 用途：写进 `AGENTS.md` §4.3 与步骤 7 归档，作为**可执行规则**的依据。

---

## 1. `--fast` 到底跑什么（读源码确认，不靠印象）

`scripts/verify.mjs:867-875`：

```js
const NO_TEST_GROUPS = [
  { id: 'heavy', steps: HEAVY_STATIC_GROUP },   // typecheck / format / lint
  { id: 'static', steps: CHECK_GROUP },         // 16 项静态检查
];

if (fast) {
  groups = NO_TEST_GROUPS;   // ← 只跑这两组，test 组整个不跑
}
```

**`--fast` = 20 项，其中不含任何一条执行代码的检查。**

| 组 | 内容 | 能抓什么 |
| --- | --- | --- |
| `heavy` | typecheck / format / lint | 类型、格式、静态规则 |
| `static` | 16 项文本/结构检查 | 死链、边界、白名单一致性、文档 |
| ~~`test`~~ | **vitest（本轮 85 files / 1501 tests）** | **行为、逻辑、文案断言** |

关键：**`static` 组的 16 项全是"文本/结构"检查**（`docs` 查死链、`patch` 查常量↔ADR、
`page-gate` 查路径字面量、`messages` 查消息路由对齐…），**没有一项执行被测代码**。

## 2. 四条 🔴 逐条归类

### 🔴-1 · `run-q2-auto.cjs` 没跑 → **`--fast` 也抓不到**（但全量能）

| 属性 | 值 |
| --- | --- |
| 归属盲区 | **外部脚本执行**（不在 verify 的任何组里，靠 `dnr-regression` 检查项比对 stamp 文件） |
| `--fast` 能抓吗 | ❌ **不能**——但它**也不是 `--fast` 特有的盲区**：`dnr-regression` 在 `static` 组里，`--fast` **会**跑它 |
| 实测 | 我跑 `--fast` 时这一项**确实报了红** |

> 精确说：🔴-1 **不是** `--fast` 的盲区，它是**所有档位都会抓到的**（因为它只在 `dnr.ts` 有改动时触发）。
> 它的成因是"跑 verify 前没跑回归脚本"，不是"选了轻档"。
> **但 `--fast` 的 `--help` 里没有提这个前置依赖**——这是可用性问题，不是盲区。

### 🔴-2 · `resolveBoundaryIdentity` 缺 `streamingIdentity` → **`--fast` 完全抓不到**

| 属性 | 值 |
| --- | --- |
| 归属盲区 | **逻辑维度缺失**（函数签名少一个参数，代码自洽、类型自洽、静态检查全过） |
| `--fast` 能抓吗 | ❌ **完全不能** |
| 为什么 | `heavy` 组的 typecheck 通过（签名与调用方一致）、lint 通过（没有未用变量）、`static` 16 项全部与这段逻辑无关 |
| 唯一能抓的 | **单测**（`feed-boundary.test.ts` 里加"`page` 模式 → 不显示"的用例） |
| 本质 | **"少了一个输入维度"这件事在类型系统里是不可见的**——`(a,b,c,d)` 和 `(a,b,c,d,e)` 都是合法签名 |

### 🔴-3 · 类型断链（4 处手抄字面量）→ **`--fast` 抓到一半，而且是运气好**

| 属性 | 值 |
| --- | --- |
| 归属盲区 | **类型契约断裂**（同一联合被手抄多份，各份不同步） |
| `--fast` 能抓吗 | ⚠️ **部分**——`heavy` 组的 typecheck **只在"值真的流过去且目标类型不含它"时报错** |
| 实测证据 | 我做的变异：把 `'page-identity'` 加进 `ProxyActivateReason` → `tsc` **报了** `TS2322`。但这**反过来**才成立：**漏掉的地方恰好没有生产调用方时，`tsc` 全程静默** |
| 本轮真实情况 | 加 `'page-identity'` 时"只改两处、漏三处"，**`tsc` 全程没报错** |
| 本质 | **`tsc` 保护的是"值的使用"，不是"值的定义一致性"**。两个不同的联合类型同时存在时，只要没有一处把 A 赋给 B，就永远不报错 |

> 这一条是本轮最重要的认知：**typecheck 绿 ≠ 类型对的**。

### 🔴-4 · 6 处用户可见字符串仍是「播放账号」→ **`--fast` 完全抓不到**

| 属性 | 值 |
| --- | --- |
| 归属盲区 | **文案**（字符串内容的语义正确性） |
| `--fast` 能抓吗 | ❌ **完全不能** |
| 为什么 | `format`/`lint` 只关心格式与规则；`static` 16 项里**没有一项检查用户可见字符串的用词** |
| 已有实证 | handoff §2.5 记着：把副标题改回旧的、把 `releaseNotes()` 换成 Q10 禁用词「解锁」，**`verify` 依然全绿** |
| 唯一能抓的 | **人工 `git diff` 审阅**（没有机械兜底） |

## 3. 归类总结

| 盲区类型 | 🔴 编号 | `--fast` | 全量 verify | 单测 | 人工 |
| --- | --- | --- | --- | --- | --- |
| 外部脚本未执行 | 🔴-1 | ⚠️ 能（在 static 组） | ✅ | — | — |
| **逻辑维度缺失** | 🔴-2 | ❌ | ❌ | ✅ **唯一** | ✅ |
| **类型契约断裂** | 🔴-3 | ⚠️ 条件性 | ⚠️ 条件性 | ✅ | ✅ |
| **文案语义** | 🔴-4 | ❌ | ❌ | ⚠️ 需要专门断言 | ✅ **唯一** |

**规律：`--fast` 的盲区恰好是"代码跑起来才暴露"的三类 + "字符串内容"这一类。**
而这三类正是本项目历史上出问题最多的（handoff §2.5 的文案、collect.ts 判据双向错误）。

## 4. 可执行规则（建议写进 `AGENTS.md` §4.3）

> **规则 A：改动了任何被 `describeXxx` / `snapshot` 消费的枚举值或联合类型 → 必须全量。**
> 理由：这类改动的错误形态是"某个分支不再被走到"或"某处少一个维度"，
> 全量里只有 `test` 组能发现，`--fast` 完全不可见。
>
> **规则 B：改动了任何用户可见字符串 → 必须人工 `git diff` 逐条审。**
> 理由：本轮 + handoff §2.5 双重实证，`verify` 对文案**零兜底**。
> 不接受"verify 绿了就是对"。
>
> **规则 C：给函数新增一个"输入维度"（多一个参数）→ 必须同时补一条"新维度导致行为变化"的测试。**
> 理由：🔴-2 的本质是"签名加了新参数但没人测新参数的效果"。
> 现有测试即使有 8 个用例覆盖该函数，**缺一个新维度就等于没测**（这正是本轮的实际情形：
> `feed-boundary.test.ts` 有 8 个 `resolveBoundaryIdentity` 用例，**全部没有 `streamingIdentity`**）。
>
> **规则 D：`dnr.ts` 有改动 → 先跑两个 DNR 脚本，再跑 verify（任一档）。**
> 理由：`dnr-regression` 是**前置项**，它红会让后续检查整组跳过
> （实测输出：`⛔ dnr-regression 是前置项，本组后续检查已跳过（结果无意义）`）。
> 先跑脚本能避免"跑了一遍 verify 但结果无意义"。

## 5. 一条对 `--help` 的建议

`node scripts/verify.mjs --help` 现在写「`--fast` 跳过 vitest，20 项（约 15–25s，改文档时够用）」。

**"改文档时够用"这个描述是准确的**，但容易被读成"改动小就够用"。
建议补一句：

> ⚠️ **`--fast` 不执行任何代码**。改动了逻辑、类型联合、用户可见文案时，
> 它的绿灯**不代表正确**——本轮实测有 3 条真 bug 在 `--fast` 下全绿。
> 判据见 §4.3 的规则 A/B/C。

## 3. 我的判据错在哪

我用的判据是：

```powershell
Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" |
  Where-Object { $_.CommandLine -match 'incognito' }
```

**它恒为 0。**

原因：Edge 的无痕窗口**不是独立进程**，它是同一浏览器进程内的另一个 profile / 分区。
命令行里根本不含 `incognito` 字样。

⇒ 「进程命令行匹配不到」被和错当成「窗口不存在」。**这是假阴性。**

更糟的是我把它写成了「排除法第 1 条：不用 bsk，用 OS 级进程查」——
**恰恰这一条是无效判据**。其余 4 条排除法也因此失去了意义：它们共同指向一个错误前提。

### 正确判据（供下一个人用）

| 用法 | 判据 |
| --- | --- |
| ✅ 可用 | `EnumWindows` + `GetWindowText`，匹配窗口标题里的 `InPrivate` |
| ✅ 可用 | `Get-Process msedge \| ? MainWindowTitle` |
| ✅ 可用 | 窗口截图后人眼确认（`read_image`） |
| ❌ **不可用** | `Get-CimInstance Win32_Process` 的 `CommandLine` 匹配 `incognito` |

## 4. 连带纠正：诊断页「读取失败」的归因

诊断页显示：

```
InPrivate 权限 / 窗口列表 / cookie 分区  => "读取失败（background 未返回这一项）"
凭据状态                                => "读取失败: Error: Extension context invalidated."
诊断日志                                => "最近 0 条"
manifest incognito                      => "读取失败"
```

我先前归因为「**SW 休眠**」。**这个归因也是错的。**

**真因**：我在 03:00 执行了 `node poc/probe/reload-extension.mjs`（重载扩展）。
MV3 扩展重载后，**已经注入到页面里的 content script 立刻 context invalidated**，
直到该页面刷新才会重新注入。

而我为了满足场景 3 的「**不许刷新页面**」判据，**全程没有刷新过 B 站页面**。
⇒ content script 从 03:00 起一直是**孤儿态**。

**这是我为了做场景 3 而自己造成的观测环境，不是产品缺陷。**

**佐证**：新开的干净标签（`1673239254`）上，桥与面板均正常工作，无任何"读取失败"。

## 7. 保留的自省

Lead 的原话：

> 「独立验证的价值不在于多一双眼睛，而在于那双眼睛没有你的预设。」

我这次**问对了**说明页的字数口径（还抓出自己 PowerShell 重编码导致的 294 vs 283），
**却在「窗口存不存在」上栽了同一类错**：

**拿一个不可靠的间接指标（进程命令行）当"看得到 / 看不到"的判据，
而没有用最直接的那个（窗口标题 / 截图）。**

教训：**当我要说"某样东西不存在"时，先确认我的探针本身能不能看到它存在。**
一个"恒为 0"的探针，和一个"真的没有"，在输出上长得一模一样。

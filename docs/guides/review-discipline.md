# 复核纪律（与有没有智能体团队无关）

> **用途**：写代码的人**不能自己说"修好了"**。这份文件规定"怎么才算验过"。
> **它不依赖任何团队功能** —— 单人 + 一个 AI、或其他不支持子代理的 Harness，
> 这份文件照样一字不改地用。
>
> 团队编排（怎么 spawn、任务卡模板、派给谁）在 [team-workflow.md](./team-workflow.md)，
> **那份只在 DSH 的智能体团队模式下有效**。本文是它的"纪律内核"，
> 两层关系是：**换个 Harness 你丢的是"谁来做"，不是"怎么算做完"。**

---

## 0. 三个不变量

任何 Harness、任何人数，这三条都成立：

| # | 不变量 | 违反的典型后果 |
| --- | --- | --- |
| 1 | **写代码的人不能自己验收** | "自己写完自己验"——M3 阶段三个错误全由此产生 |
| 2 | **报告是声明，不是事实** | 别人（或你自己上一次）说"✅ 全过"，不等于它现在过 |
| 3 | **绿了不等于修好了** | 测试绿了、产品行为没变——最贵的假安全感 |

> 第 3 条是 2026-11-15 实测的：`login-outcome.ts` 的 `assumed` 分支还是老代码，
> 但 `verify` 21 项全绿，因为**守住它的那条测试被改成了别的形状**。
> 判据：`verify` 绿 + **改动文件的 mtime 比最后一次"解释"更早** ⇒ 怀疑测试被改，不是代码被修。

**没有第二个实体可派时怎么办**：把"验证"降级成"**换口径重测**"——
不是复述同一个检查，而是换一个能反驳自己的口径（换数据源、换断言层、换环境、
或把关键判据改回去看它是否变红）。**换口径比换人更重要。**

## 1. 验收门（每个实现改动收尾都跑）

**跑哪一档由改动性质决定 → 见 [AGENTS.md](../../AGENTS.md) §4.3 的触发路由表。本文不复制那张表。**

- [ ] **跑哪一档由改动性质决定，不由"省时间"决定。** 判不准 → 跑全量。
      一处改动涉及多个文件时，取其中最重的那档。
- [ ] **验收方必须跑全量 `node scripts/verify.mjs`，不享受任何分级。**
      用被验者自己的口径验被验者，那不算验证。
- [ ] 反例验证：关键判据改回去，相关测试必须红（见 §3）
- [ ] `git status` 干净；提交前 `check-secrets` 绿（pre-commit 钩子会自动跑）
- [ ] 结构性改动先有 ADR；行为变化先改 `AGENTS.md` §3 或 ADR
- [ ] **构建产物核对**：改动要到了浏览器，必须 `node node_modules\wxt\bin\wxt.mjs build`
      并核对 `.output/chrome-mv3/**` 的时间戳与关键词（`verify` 测的是 `src/`，
      浏览器加载的是 `.output/`，**中间隔着 build**）

## 2. 独立复跑要查的四类

只写"独立复跑"太空泛。这四类是本项目实际栽过的：

| # | 查什么 | 为什么 |
| --- | --- | --- |
| 1 | **分母有没有来源** | 曾用脚本里手写的无来源数组当"上游 37 个分类"，据此算覆盖率 —— 分母假，整句结论不成立 |
| 2 | **样本内结论有没有被外推** | 只在首页测选择器命中 0，就宣布"上游选择器在 B站 全失效"；视频页其实仍在用 |
| 3 | **A/B 对照的两态是否真的不同** | 脚本拿旧 style id 移除样式，取不到就静默跳过 → 两态测同一状态、差值恒 0 的**假绿** |
| 4 | **失效是否静默** | 选择器命中 0、`getComputedStyle` 读不到、容器找不到 —— 都不报错。要看有没有留痕 |

## 3. 反例验证的四个**额外**前提

"改回去必须红"只保证了**一半**。四个前提缺任一，反例就是**假红**：

| 前提 | 缺了会怎样 |
| --- | --- |
| **A/B 两态必须真的不同** | 移除手段失效时两态测的是同一状态、差值为 0，**"没变化"被当成通过** |
| **测的是当前构建** | 改完代码没重载扩展，测的是旧产物 —— 结论与代码**毫无关系** |
| **口径排除了"天然如此"** | B站 自己隐藏的元素被算成"我们隐藏的"，反例恒不红 |
| **反例改动只影响自己** | 共享工作区时，隔离手段会**卷走别人的未提交改动** —— 见 §3.1 |

**做法**：A/B 脚本先断言两态不同；真机前确认已重载；用**差分**判据而非绝对值。

### 3.1 反例验证不许用全局 `git stash`（2026-11-10 实测踩过）

**发生了什么**：两次反例验证各用了一次 `git stash`，把**整个工作区 20 个文件**一起收走 ——
包括另一个成员正在写的文档和第三个人的脚本改动。两个成员几乎同时发现"文件凭空消失"。

**为什么危险**：`git stash` 的作用域是**整个工作区**（带不带路径参数都可能如此，见下），
而组队模式恰恰是**多人共享同一个工作区**。
收走别人的改动不会报错，只会让对方看到"文件凭空消失"。
更危险的是：**两个成员同时 pop 会互相覆盖。**

**正确做法**（按优先级）：

| 做法 | 适用 |
| --- | --- |
| 反例改动**直接写在临时副本**里（如 `%TEMP%` 下的同构文件），不碰仓库 | ✅ 首选 |
| `git worktree add` 开独立副本，在副本里做反例 | 改动面大时 |
| `git stash push -- <只列自己的文件>` | ⚠️ **次选且极易出错**，见下 |
| ❌ `git stash`（**任何形式**）、`git checkout .`、`git restore .`、`git reset --hard`、`git clean -fdx` | **禁止** |

**⚠️ 「加个 `-- <路径>` 就安全」是错的**（2026-11-10 实测）：

第一次事故后，记录里先写的是「禁止**无路径**的 `git stash`」。
紧接着第二次事故用的正是带路径的形式 —— `git stash push --keep-index --include-untracked -- . ':!rank.ts'` ——
**依然收走了整个工作区**，因为 `-- .` 就是「全仓」。所以：

- **`git stash` 无论带不带 pathspec，在共享工作区一律禁止**
- 若确实要用路径形式，必须**逐个列出自己的文件**，且 `-- .` / `-- :/` / `-- '*'` 这类通配一律视为全仓

**同理禁止**：`git reset --hard`、`git clean -fd` —— 它们的作用域也是整个工作区。

> 发现工作区异常时：**不要替别人恢复**（pop / reset 都会和对方撞车），
> 就地停下并报告，由文档/范围 owner 判定归属。

### 3.2 反例脚本自己也要验

反例报"红"之前，**先用正确输入证明它会报绿**。

2026-11-15 两个探针各翻车一次：v1 因为模块级状态跨用例存活，误报"权限 false 没拦住建窗"；
v2 把合法路径算成了 bug。共性结论：**「把好的说成坏的」和「把坏的说成好的」一样有害。**

### 3.3 备份范围必须严格等于变异范围

做反例要备份文件。备份列表**大于**变异列表时，恢复动作会覆盖掉**别人在这段时间里的写入**。
两条硬规则：

1. **备份范围 == 变异范围**，不许顺手多备
2. `restore()` 之前核「当前文件 SHA 还是不是备份时的 SHA」，**不等就停手**

## 4. 读别人（或自己上次）的验证报告

- 说 ✅，**也不等于完成** —— 你自己再跑一遍关键项（§0 第 2 条）
- 说 ❌ 或"未验证"，**优先当成待修项**，不要解释成"应该没问题"
- 说你写错了，**先按它说的重测**，不要先辩解
- 报告里的每个数字，都要能指到**命令与输出**；指不到的一律降级为"未验证"
- **口径错误也要指出来**：锚定在"我测出来是 X"的任务描述会让验收方失去独立性

## 5. 并发写工作区

单人时这条退化为"别并行改同一个文件"，但破坏性不变：

1. **一文件一 writer**；热文件串行：`main-world.js`、`dnr.ts`、`content.ts`、`messages.ts`、`routes.ts`、`tokens.css`
2. **开工前先扫 mtime** 确认静默；**"改动已在工作区" ≠ "写完了"**
3. 同一份文件上**不许同时**做两件写事（反例 / 修复 / 格式化）
4. 观测期间别的进程改了代码 → **本轮观测作废**，从头重取基线

## 6. 真机单点（**含 Lead / 自己**）

**规则**：同一时间只有一个 tester 驱动 `bsk` / `reload-extension` / 浏览器。

| 谁 | 允许的操作 |
| --- | --- |
| **持有者**（当轮 tester） | 全部 `bsk` / `reload-extension` / 导航 / 截图 |
| **其他任何人（含文档 owner）** | **一律不碰浏览器**；只做静态检查、读代码、写文档 |

**交接三步**（缺一不可）：

1. 交接前 tester 执行 `bsk session stop <sid>` 显式释放
2. 在任务板/交接记录里注明"浏览器持有者"是谁
3. 接手前**先确认对方已停手**——不要靠"应该跑完了"来判断

**持有期间有人改了代码 → 必须立刻通知持有者**：

- 构建产物变了，持有者测的是旧版本 → **结论作废**
- `reload-extension` 会重启浏览器 → **session 直接死**

持有者收到通知后**从头重取基线**，不要续用之前的测量。

**两种违反形态**（都真实发生过）：

- 别人在测时你去导航/截图 —— 抢走 Agent Window
- **自己该把验证交出去，却自己上手** —— 违反 §0 第 1 条。**代码是你写的，就更该让别人验。**

---

## 7. 禁止项（违反即停）

- 改 `AGENTS.md` §3 的 12 条决策、未授权的新改写路径/主机（§5.5）
- 加依赖、加检查项、改命令入口（§7）
- 在脏工作区上打包（G6 clean-tree 门会拒）
- 把真实 mid/昵称/凭据写进任何文件或提交信息（`check-secrets`）
- 并行改同一热文件（§5）、多人同时驱动同一个浏览器（§6）
- 自己写的代码自己签"✅ 修好了"（§0）

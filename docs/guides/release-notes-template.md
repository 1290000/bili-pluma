# Release 说明模板

> Release 页是**唯一会被陌生人在 GitHub 上直接读到**的地方，也最容易被截图传播，
> 因此措辞比 README 更需要克制。
>
> 由 `scripts/package.mjs` 填好版本号后落在 `dist/release-notes.md`，
> 发布时用 `gh release create --notes-file dist/release-notes.md`。
>
> 分发边界见 [ADR 0018](../decisions/0018-ship-built-artifacts.md)。

---

## 写作原则

| 要 | 不要 |
| --- | --- |
| 中性动词：下载 / 加载 / 构建 | 「一键安装」「开箱即用」「发布上线」 |
| 主动写「也可以自己从源码构建」 | 只给 zip，让编译变成隐藏选项 |
| 主动列「已知限制」 | 隐去不支持的东西 |
| 「修复过的 bug」用中性描述 | 「破解」「解锁会员」「绕过限制」 |
| 短 | 长（读的人不关心细节，关心的不读细节） |

**最忌讳的两个词**：`破解` / `解锁会员`。它们会直接影响对方如何定性这件事。

## 模板

```markdown
## Pluma <版本>

B站双账号画质助手。用主账号浏览、点赞、收藏，让一个大会员账号专门负责取流。

### 下载

| 文件 | 内容 |
| --- | --- |
| `pluma-<版本>.zip` | 构建产物，解压后在 `edge://extensions` 加载 |
| `pluma-<版本>-with-source.zip` | 同上 + 完整源码 |

也可以自己从源码构建：`pnpm install && pnpm build`，加载 `.output/chrome-mv3`。

这份产物由本项目开发者构建，未经过浏览器扩展商店签名，仅供学习交流使用。

### 这一版包含什么

<按实际填，只写用户能感知的>

- 4K / 1080P60 / HDR / Hi-Res 取流
- 主账号始终是浏览器登录的那个号：点赞、收藏、评论、历史、观看进度都归它
- 设置页三个分区：账号 / 诊断 / 显示

### 边界

- **不绕过付费墙**：会员专享番剧、电影仍需购买
- **不伪装会员标识**：界面显示你的真实状态
- **不解锁地区限制**
- **与哔哩哔哩官方无任何关联**，未获授权或认可

### 已知限制

- 番剧 / 直播不支持

### 许可证

GPL-3.0-only + [附加条款](<仓库根目录 ADDITIONAL-TERMS.md 的链接>)
```

---

## 关于「已知限制」写什么

**只写「不支持且有价值让人提前知道」的东西。** 判据：

| 该写 | 不该写 |
| --- | --- |
| 功能**没做**（番剧 / 直播） | 功能**做了但未实测**（>116 分钟流地址刷新 —— 那是我们的待办，不是用户的问题） |
| 用户会直接撞上的 | 实现细节（杜比视界为什么没有徽章 —— 能播就行，说了反而引出疑问） |

**"未实测"和"不支持"性质完全不同**：前者是我们的欠账，写进 Release 会让读者以为
这版有已知缺陷；后者是范围决定，写清楚能省掉重复提问。

未实测项只在 [03-open-questions.md](../03-open-questions.md) 里跟踪。

## 检查清单（发布前逐条过）

- [ ] 标题是 `Pluma <版本>`，没有「发布！」之类的词
- [ ] 两个 zip 都在下载表里，文件名是 `pluma-<版本>.zip` 格式（不带 `v`、不带浏览器名）
- [ ] **有「也可以自己从源码构建」那句**
- [ ] **有「未经商店签名，仅供学习交流使用」那句**
- [ ] 「边界」四条齐全
- [ ] 「已知限制」只写功能不支持的项
- [ ] 全文没有 `破解` / `解锁会员` / `一键安装` / `开箱即用`
- [ ] 没有「感谢支持，欢迎 Star」之类经营项目的话

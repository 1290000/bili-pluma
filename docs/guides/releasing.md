# 发布流程

> 本项目**只发源码**。本节说明为什么，以及如果将来改变主意要注意什么。

---

## 红线（在任何情况下都不要越过）

| 红线 | 原因 |
| --- | --- |
| **不上架 Chrome / Edge 商店** | B站投诉后必下架；且"修改请求头"类扩展审核本就严格。详见 Q16 |
| **不发预编译 zip / crx** | 减少"提供可用侵权工具"的观感。bilibili-API-collect 只删文档就过关了 |
| **不提供跳过付费墙的能力** | 这是能否站住的分界线，也是免责声明里"不绕过付费墙"这句话的前提（见 Q4） |
| **不做任何形式商业化** | 收钱会把性质从"个人工具"变成"商业服务"（见 Q10） |
| **不主动做 SEO / 推广** | 降低被发现概率（但别指望有效） |
| **不在 README 宣传许可证** | 放显眼位置会给用户"这是正经商业项目"的错觉，放大风险感知 |

---

## 发布流程（源码版）

### 1. 版本号

遵循语义化版本 `MAJOR.MINOR.PATCH`：

- `MAJOR`：白名单路径变化导致行为不兼容 / 消息协议 breaking change
- `MINOR`：新增支持的场景、新增界面
- `PATCH`：修 bug、调整文案

同步更新 `src/manifest.json` 的 `version`。

### 2. 发布前检查

```bash
# 全部通过才能发
npm run typecheck      # tsc --noEmit
npm run lint           # eslint，含依赖方向规则
npm run check:boundaries   # scripts/check-boundaries.ts
npm test               # vitest，core 层单测
npm run build          # 打包，检查产物体积
```

### 3. 人工冒烟测试

在 Chrome 和 Edge 各跑一遍：

- [ ] 首次安装 → badge 出现小圆点 → popup 显示"未配置"
- [ ] 扫码登录播放账号 → 成功 → popup 显示"已接管"
- [ ] 打开一个 4K 视频 → 画质菜单出现 4K/1080P60
- [ ] 点赞一条视频 → 检查是否记在主账号（不是播放账号）
- [ ] 播放 30 秒 → 检查历史记录是否出现在主账号
- [ ] 拔掉播放账号凭据（模拟失效）→ popup 显示"凭据失效"
- [ ] 打开非视频页 → popup 显示"未生效"

### 4. 更新 CHANGELOG.md

格式：

```markdown
## [1.0.0] - 2026-11-XX

### 新增
- 支持 4K / 1080P60 / HDR / Hi-Res 取流

### 变更
- 白名单新增 XXX 路径

### 修复
- 修复多标签页并发时的规则冲突
```

**不要在这个时候写"修复了某某接口破解"这种措辞**。全部用中性描述。

### 5. 打 Tag 并发布

```bash
git tag -a v1.0.0 -m "v1.0.0"
git push origin v1.0.0
gh release create v1.0.0 --notes-file CHANGELOG.md
```

**Release 只放源码归档（GitHub 自动生成），不上传任何构建产物。**

## 收到律师函怎么办

这件事的预案写在 [03-open-questions.md](../03-open-questions.md) 的 Q16。这里只列动作要点：

1. **不要慌，不要公开发泄。** 前几个项目的作者都很克制，反而保留了社区同情。
2. **archived，而不是删除。** 删除会被解读为心虚，归档是体面的处理。
3. **README 换成一封说明**："因收到权利方通知，本项目停止维护"，保留原代码。
4. **不要在 issue 区号召"大家快去 fork"**——这会让事情升级。
5. **区分对方主张**：是不正当竞争（性质较轻）还是著作权侵权（需认真对待）。

**准备这句模板，需要时直接改：**

> 本项目已于 [日期] 收到权利方委托律师事务所的通知，即日起停止维护。
> 仓库代码保持原样供已下载者参考，不再更新，也不提供任何形式的技术支持。
> 感谢所有使用者与贡献者。

## 如果将来要改分发方式

**先问自己三个问题**：

1. 这么做能带来什么，是用户真的需要，还是我想让项目"看起来更正式"？
2. 风险增加的部分，我是否愿意承担？
3. 出事了，我能不能承受这个后果？

**任何一条答不上来，就不要改。**

如果确实要上架商店，至少做到：

- 上架前咨询一次法律意见（哪怕只是付费咨询半小时）
- 准备一份"下架就归档"的预案
- 不要在 README 里用"官方""正版"之类的字眼
- 不要用 B 站品牌色（粉色）做图标，避免被误认为官方插件

# Pluma UI 设计规范（B站双账号画质助手）

> 项目名 **Pluma** / 仓库名 `bili-pluma`。界面中品牌名统一显示为 **Pluma**。
> 形态：纯 MV3 扩展（见 [01-architecture.md](./01-architecture.md)）
> **技术实现**：popup / options / login window 用 **Preact**；页内角标用**原生 DOM + Shadow DOM**；样式用**原生 CSS 变量**。
> 完整技术选型与目录位置见 [04-project-structure.md](./04-project-structure.md) §〇。
> 范围：popup / options / 页内注入 / 首次引导 四类界面

---

## 0. 一条铁律

**Popup 是"查看器"，不是"操作台"。**

用户点开 popup 的心理预期是 2 秒内确认"现在有没有生效"。如果界面需要他读、需要他点、需要他思考，设计就是失败的。

判断标准：**popup 上的每一个元素，都必须能回答"我现在应该担心吗"这个唯一问题。** 不能回答的，全部移出 popup。

---

## 1. 尺寸与技术约束（先看这个，否则设计白做）

| 约束 | 数值 | 影响 |
|---|---|---|
| Popup 最大宽 | 800px | 但实际应控制在 **360–400px**，更宽会显得空 |
| Popup 最大高 | 600px | 超过出现滚动条，体验急剧下降 |
| **Popup 失焦即关闭** | — | **致命约束**：扫码登录、长任务、需要切窗口的流程都不能放这里 |
| Popup 无固定高度 | 内容撑开 | 不同状态高度不一致会导致"抖动"，需给主容器设 `min-height` |
| Popup 不能调 `window.close()` 外的窗口控制 | — | 无法做"最小化到托盘" |
| Service Worker | 30s 无事件休眠 | **不做长任务**：本项目的取流由页面发起、换 Cookie 由 DNR 完成，SW 只做消息转发。因此**不申请 `alarms`**（[ADR 0015](./decisions/0015-lazy-health-check-no-alarms.md)） |
| Options 页 | 全屏标签页 | 唯一能放复杂 UI 的地方 |

**推论**：扫码登录必须开独立窗口或 options 页。绝不能在 popup 里放二维码——用户拿手机扫的时候 popup 已经关了。

## 2. Popup 设计

### 2.1 信息架构（自上而下，按重要性递减）

```
┌─────────────────────────────────────┐
│ 1. 状态条  品牌 + 接管状态 + 健康点   │  ← 20% 注意力，2 秒内可读完
├─────────────────────────────────────┤
│ 2. 当前页解锁画质（含对比）           │  ← 40% 注意力，核心价值证明
├─────────────────────────────────────┤
│ 3. 双账号卡片 A / B                  │  ← 25% 注意力，信任建立
├─────────────────────────────────────┤
│ 4. 快捷开关（自动接管取流）            │  ← 10%
├─────────────────────────────────────┤
│ 5. 底部操作（播放账号 / 设置）        │  ← 5%
└─────────────────────────────────────┘
总高控制在 460–520px
```

### 2.2 状态条（最关键的 20px）

左侧：品牌名 + 状态胶囊。右侧：绿点 + 一句话。

状态胶囊共 **7** 种，必须互斥且唯一：

| 胶囊文案 | 颜色 | 触发条件 | 右侧文字 |
|---|---|---|---|
| 已接管 | success | 有播放账号 + 开关开 + 当前页是受支持的播放页 | 代理正常 |
| 未生效 | 中性 | 有播放账号 + 但当前页不是播放页 | 等待视频页 |
| 未配置 | 中性 | 无播放账号 | 点击登录 |
| 凭据失效 | danger | 播放账号 nav 返回 -101 | 需重新扫码 |
| 已降级 | warning | 有播放账号但代理连续失败 | 查看诊断 |
| 已停用 | 中性 | 用户关掉了总开关 | 当前使用主账号画质 |
| 异常 | warn | 开关开着但 DNR 规则没装上 | 关闭再开启一次 |

> ⚠️ 这里曾写"共 5 种"，漏了「已停用」与「异常」——而它们恰恰是用户最容易遇到的两种情况。
> 数字以 `src/core/ui/popup-state.ts` 的 `PopupState`（**8 个枚举值**）为准，
> `credential-missing` 与 `expired` 共用「凭据失效」这一种胶囊，所以是 **8 → 7**。

**设计要点**：
- 胶囊文案必须短（2–3 字），因为用户不会读长句。
- **不要用"开启/关闭"这类描述开关状态的词**，要用"已接管/未生效"这类描述**结果**的词。用户关心结果。
- 绿点只在"已接管"和"代理正常"时显示，其他状态用对应色点或隐藏。

### 2.3 当前页解锁画质（核心价值区）

> ✅ **已实现。** 视图模型在 `src/core/playinfo/summary-view.ts`（纯函数，16 个单测），
> 数据来自 content 直连应答（`docs/protocols/messages.md` 通道 D）。
> **没有 HDR 徽章** —— 四个可用信号全被实测证伪，见 [ADR 0014](./decisions/0014-quality-compare-from-page-data.md)。
> **番剧/电影页也走这条**（`parsePlayPage()` 判据，2026-10-28 修）。

这是整个 popup 唯一不能省的部分。

```
当前页面 · BV1xx411c7mD
┌───────────────────────────────────┐
│ 已解锁          主账号仅可用 1080P  │
│ [4K] [60fps] [Hi-Res]             │
└───────────────────────────────────┘
```

**三个设计决策**：

1. **必须有对比**。"主账号仅可用 1080P"这行小字不是装饰，它是价值锚点。没有对比，用户感受不到这个插件做了什么。
2. **徽章用"已解锁"而非"可用"**。语义差异：前者隐含"因为插件才有的"，后者中性。
3. **超出宽度换行，不横向滚动**。最多展示 6 个徽章（`MAX_BADGES`），超出的截断。

**徽章规则**（`unlockedBadges()`，代码为准）：

| 徽章 | 条件 |
| --- | --- |
| `HDR` / `1080P+` / `1080P` / `4K` … | **`dash.video[].id` 命中 `QUALITY_NAMES`**（[ADR 0026](./decisions/0026-quality-badge-by-id.md)） |
| `60fps` | **最高高度那一档**的帧率 ≥ 50（30fps 不出徽章，那是默认值） |
| `Hi-Res` | `dash.flac.audio` 存在 |
| `杜比全景声` | `dash.dolby.audio` 非空 |
| `杜比视界` | `dash.dolby.vision === true`（语义是"本视频**提供**"） |

> ⚠️ **画质档看 `id`，不看 `height`（2026-10-29 改，ADR 0026）。**
> 同一高度下 B 站分多个档：`125`(HDR) / `112`(1080P 高码率) / `80`(1080P) **全是 height 1080**。
> 用 `heightLabel(1080)` 会把三档抹成一个「1080P」—— 用户真机指出过这一点
> （「我测的这个番剧有 1080p 高码率还有 HDR 真彩」）。
> `id` 取不到时才退回 `heightLabel`，**不许猜档位**。
>
> ⚠️ ADR 0014 原本写「HDR 永不产出」，那条针对的是**运行时信号**
> （`(video-dynamic-range: high)` 等，确实判不了）。`id === 125` 是服务端在真实轨道上
> 标注的档位，是另一类事实 —— 修订理由见 ADR 0026。
> **页内角标不受影响**，它仍然只用 `videoHeight` + SourceBuffer 实际 mime。

**标题只有六种**（`describeUnlock()` 的返回值全集，代码为准）：

| 标题 | 何时 | 不许混用 |
| --- | --- | --- |
| `已解锁` | 两侧能比，且播放账号更强 | — |
| `无提升（源限制）` | 两侧能比、无提升，且两侧能力**完全相同** | 与下一行含义不同，不许合并 |
| `没有提升` | 两侧能比、无提升，但两侧**不完全相同**（可能是代理没生效） | 同上 |
| `无法对比` | 有播放账号数据，但主账号基线不可用 | — |
| `未登录主账号` | `DedeUserID` 读不到（DOM 就绪后仍读不到） | ⚠️ **不许落到「无提升（源限制）」** |
| `等待取流…` | 播放账号侧还没有数据 | 此时不显示任何徽章 |

> ⚠️ 「未登录主账号」这一行是 2026-10-26 补的。游客态两侧都是 480P，
> `diffCapability` 会判成"两侧相同"，若不单独拦一下就会显示「无提升（源限制）」——
> 那等于告诉用户"这个视频本来只有 480P"，而真相是他没登录主账号。

**数据来源**（**不要重新请求**，全用已有数据）：

| 侧 | 来源 |
| --- | --- |
| 播放账号（徽章） | 页面自己那次 playurl 响应里的 `dash`（已被 DNR 换成播放账号身份） |
| 主账号（锚点） | `document_start` 那份 SSR 的 `__playinfo__` 里的 `dash` |

> ⚠️ **游客页不 SSR `__playinfo__`**（2026-10-26 InPrivate 实测）。所以未登录时基线恒为
> "不存在"，§2.3 会走「未登录主账号」那条，不会落到「无法对比」——
> 后者只说明"数据缺"，不告诉用户该去登录。

⚠️ **不用 `accept_quality`** —— 未登录时它就返回含 8K 的假数组（`poc/verify/RESULT.md` §四）。
⚠️ **不用 `<video>.videoHeight`** —— 那是"实际在播"，受用户手动选择影响，不是能力上限。
（角标才用 `videoHeight`，因为它要报"当前画面"。两者职责不同，别混。）

**边界情况**：
- 视频本身最高只有 1080P → 标题显示"无提升（源限制）"，避免用户以为是插件没生效。
- 主账号基线拿不到（SSR 缺失 / 客户端写入）→ 锚点如实写"主账号基线未知/不可用"，**不编数字**。
- **主账号未登录**（游客）→ 标题「未登录主账号」+ 锚点「主账号未登录，无对比基线」。
  徽章仍按播放账号实际拿到的显示（不隐瞒事实），但不做任何"提升"承诺。
- 版权番剧需付费 → 显示"N 集需大会员或购买"，给出具体数字。
  （番剧/国创/电影已支持，见 [ADR 0019](./decisions/0019-pgc-async-playurl-injection.md)；付费集仍要播放账号自己有观看权）

**PGC 页（番剧 / 国创 / 电影）是第七种标题：`已取得 4K`**
（`pgcTitle()`，[ADR 0024](./decisions/0024-pgc-no-primary-baseline.md)）。
PGC 页没有主账号基线，也不去取，所以上面六种标题**一个都不许用**：

| | PGC 页 | 为什么 |
| --- | --- | --- |
| 标题 | `已取得 HDR` / `已取得 4K` / 已取得播放账号的画质 | **不许说「已解锁」** —— 那是能力声明，没有对比就没有证据 |
| 锚点 | `播放账号提供` | **只写来源，不写解释**。不许补「此处不做主账号对比」—— 那是给开发者看的，占用户注意力却回答他没问过的问题（2026-10-29 用户要求删） |
| 徽章 | **过滤掉 `1080P`/`720P`/`480P`/`360P`** | **试看本来就能看 1080P**（限制的是时长不是分辨率）。标出来等于说"你能看 1080P"，是废话，不是价值证明（`PGC_HIDDEN_BADGES`） |
| 标题取档 | 取**过滤后**剩下的最高档 | 否则会出现"徽章全空、标题却写已取得 1080P"的矛盾。全被过滤光时退回「已取得播放账号的画质」，**不编档位** |

> ⚠️ 番剧页曾经整块 §2.3 都不显示（停在「正在读取本页取流数据…」）。
> 根因是三处断点叠加：PGC 页不登记 `PageState`、取流结果不回流入 `PageState`、
> `pickData` 不认识 `{code, result}` 形状。**这不是"PGC 不支持"，是三个 bug。**
> 细节与反向验证见 ADR 0024。

### 2.4 双账号卡片（信任建立区）

> ✅ **已实现**：`entrypoints/popup/main.tsx` 的 `.pair`。
> A 行灰底（只读）、B 行信息色底（可点，就地展开与 §2.6 相同的菜单）。
> 实测 popup 高度 422px（上限 600）。
>
> - **A 的等级**来自页面 `__INITIAL_STATE__.user.level_info.current_level`，
>   形状**未经实测确认**，所以容错读取：拿不到就显示「只读」，**不编 LV 数字**
> - A 的昵称只在打开过播放页时才有，否则显示"打开视频页后可见"
>   （**番剧 / 国创 / 电影页也算播放页** —— 2026-10-29 修，之前 PGC 页整份数据都产不出来，
>   见 ADR 0024）
> - **非播放页读 `storage.local` 里的显示档案**（[ADR 0025](./decisions/0025-cache-primary-display-profile.md)）：
>   首页/空间/收藏夹点开也能看到昵称，来源是"上次在播放页看到的那份"。
>   ⚠️ **播放页绝不用缓存兜底** —— 那会把游客显示成"某个昵称"（可能是上一个账号的），
>   宁可显示「未登录」。也**不显示"3 天前看到"**：过期是内部卫生，不该变成 UI 上的疑虑
> - B 的副标题是「仅取流 · 到期日（相对）」，右侧标签是会员类型 —— 两者不重复

两个卡片的**视觉层级必须刻意拉开**：

| | 主账号 A | 播放账号 B |
|---|---|---|
| 头像底色 | 灰（`background-secondary`） | 信息色（`background-info`） |
| 副标题 | `收藏 · 点赞 · 评论 · 历史` | `仅取流 · 到期日（相对，如「23 天后」）` |
| 右侧标签 | LV6 等真实等级（灰） | 会员类型（信息色） |
| 可点击 | 否 | 是（打开切换菜单） |

**为什么这样设计**：用户的潜在恐惧是"我的号会不会被盗/被切走"。视觉上要让 B 看起来像一个**受控的工具**，而不是另一个"活跃账号"。所以 B 的副标题是"仅取流"，这是在明确职责边界。A 的副标题列出四项社交行为，是在确认"这些还是你的"。

**B 卡片必须显示到期日**，因为它会驱动续费决策，也是"为什么突然失效"的最常见答案。

### 2.5 快捷开关

**v1 只放一个开关。**

| 开关 | 副标题 | 默认 |
|---|---|---|
| 自动接管取流 | 无（主功能，顾名思义） | 开 |

**"伪装会员标识"已在 Q12 决策中移除（v1 不做）**。原因见待确认清单 Q12：收益小（只是界面顺眼）、有风控风险、有伦理问题（用户误以为自己有会员）。

## 3. Popup 的状态（8 个枚举值 → 7 种界面表现，全部已实现）

只设计正常状态是新手常见错误。**原设计 5 种，实装时发现必须再加 2 种**——
「已停用」和「异常」不是细节，而是用户最容易遇到的两种情况。

> **以 `src/core/ui/popup-state.ts` 的 `PopupState` 为准**，下表是文档与代码的映射。
> 改状态时两边都要动，否则又会出现"规范说 5 种、代码有 8 个"这种漂移。
>
> **为什么要区分两个数字**：`credential-missing` 与 `expired` 在界面上共用「凭据失效」一种胶囊，
> 所以枚举值是 8、用户能看到的胶囊是 7。只写一个数字，下一个人必然数错（已经数错过两次）。

| 代码 `state` | 状态胶囊 | 对应本节 |
| --- | --- | --- |
| `not-configured` | 未配置 | 状态 1 |
| `active` | 已接管 | 状态 2 |
| `credential-missing` / `expired` | 凭据失效 | 状态 3 |
| `degraded` | 已降级 | 状态 4 |
| `stopped` | 已停用 | **状态 6（实现新增）** |
| `inconsistent` | 异常 | **状态 7（实现新增）** |
| `not-video` | 未生效 | 状态 5（2026-10-26 补齐） |

### 状态 1：未配置（首次使用）
- 状态胶囊：未配置
- 主体：居中空状态图示 + 一句话 + 主按钮"扫码登录播放账号"
- 底部小字：**"主账号无需配置，自动读取当前浏览器登录"** ← 这句极其重要，消除"我要不要把主账号密码也给出去"的疑虑

### 状态 2：正常接管
见 §2

### 状态 3：凭据失效
- 状态胶囊：凭据失效（danger）
- 顶部 danger 边框卡片：标题"播放账号登录已过期" + 说明"B 站在别处登出了此账号，或凭据已超 180 天。当前已回退为主账号画质。"
- 账号摘要行："大会员号 · 3 天前失效"
- 主按钮：重新扫码（danger 色描边）

**关键**：必须给出**归因**（"在别处登出"）和**后果**（"已回退为主账号画质"）。否则用户会反复点重试。

### 状态 4：已降级（代理失败但可播）
- 状态胶囊：已降级（warning）
- 卡片：标题"取流接口已被代理，但返回异常" + 错误码与含义（如 `-412 风控`）
- 一句话安抚：**"已自动回退主账号身份，视频可正常播放。"**
- **成功率条形图**（12 根柱 = 最近 1 小时 × 5 分钟一桶）
- 按钮：查看诊断日志

> ✅ **已实现**：`core/playinfo/stats.ts` 的 `barStates()` + popup 的 `.rate-*`。
>
> **颜色是唯一编码，高度刻意等高** —— 用高度表示样本数会暗示一种不存在的精度。
>
> | 状态 | 含义 | 颜色 |
> | --- | --- | --- |
> | `ok` | 该窗口全成功 | 信息色（与「已接管」同色） |
> | `partial` | 有成功也有失败 | 琥珀 |
> | `fail` | 该窗口全失败 | 红 |
> | `empty` | **该窗口没有任何请求** | **灰** |
>
> ⚠️ `empty` 必须画灰，**不能画红**：playurl 一小时里大部分桶本来就是空的
> （只在页面加载和切 P 时调），画红等于谎报"一直在失败"。
>
> ⚠️ **显示条件放宽了**：规格原写"只在已降级态显示"，实现改成"**只要有失败就显示**"。
> 因为 1 次失败 / 3 次请求 = 67% 成功率，够不上 `DEGRADED_RATE`(0.6) 的阈值，
> 但那种情况恰恰最需要这张图。全绿时不画 —— 那是噪音。
>
> 📌 **所以"看不到这张图"通常是正常的，不是 bug**（2026-10-27 用户问过）。
> 判据在 `entrypoints/popup/main.tsx`：`hasTrouble = bars.some(s => s === 'partial' || s === 'fail')`。
> 全程成功 → 12 根柱子全是 `ok`/`empty` → 不渲染。
> 要看到它，得先制造一次取流失败（例如关掉总开关后某个页面报到失败）。
> **已决定保持现状**：1 小时里大部分桶本来就是空的，常驻显示会是一排灰格子。

### 状态 5：非视频页

- 状态胶囊：未生效（neutral）
- **主体与 §2.3 区域都不渲染任何文字**
- 排序：**已停用 > 未生效 > 凭据校验**。用户自己关掉开关时，"已停用"最能解释当下；
  他在首页时也不该被催着去重扫凭据（扫完也没得看）

> ⚠️ **这一块经过了三次删减，别再往回收（2026-10-29 用户第三次要求后定稿）**：
>
> | 轮次 | 文案 | 结局 |
> | --- | --- | --- |
> | 原始 | 状态行「当前页不是视频页，打开任意视频查看效果」+ §2.3「打开任意视频页查看效果」 | 同一句说两遍 |
> | 一改 | 状态行缩成「当前页不是播放页」，§2.3 改成「打开视频或番剧后，这里会显示该页已解锁的画质」 | 用户要求都删 |
> | **定稿** | **两处都不渲染** | 胶囊「未生效」已经说明一切 |
>
> 判据：**用户已经知道自己在哪个页面。** 再写一遍是把显而易见的事说一遍，
> 白白占掉 popup 有限的高度。
>
> 非视频页的 popup 由「胶囊 + 两张账号卡 + 开关」构成 —— 这是有意的留白，不是缺组件。

> 实现：`PopupState` 里是 `'not-video'`，判据是活动标签页 URL 能否被
> `parsePlayPage()` 解析（`entrypoints/popup/main.tsx` 的 `readPageView()`）——
> **不是 `/video/` 正则**。曾经用 `/video/` 当闸门，番剧页被误判成「未生效」，
> 连带 §2.3 的画质对比也永远不显示（2026-10-28 审查修）。
>
> `PopupView.line` 现在是**可选字段**：已接管 / 已停用 / 未生效都不写解释；
> `凭据失效` / `已降级` / 未配置引导仍要写 —— 那几句带归因和动作，删了用户不知道做什么。

### 状态 6：已停用（用户关掉了总开关）

- 状态胶囊：已停用（neutral）
- 一句话："当前使用主账号画质"

**必须排在「凭据失效」之前。** 用户自己把开关关掉时，那是当下最能解释"为什么没 4K"的事实；
如果先报"凭据失效"，用户会去重扫一个本来好用的号，扫完发现还是没画质——因为开关压根没开。
这是纯粹的误导。

**顺序原则**：能解释当前结果的状态优先，与用户操作相关的优先于与后台校验相关的。

### 状态 7：~~异常（开关开着但规则没装上）~~ —— **已移除（2026-10-29）**

原设计：`ruleCount === 0` → 胶囊「异常」+ 一句话「开关开着但规则没装上，请关闭再开启一次」。

**用户实测后要求去掉，理由是它经常报错情：**

> 「番剧页从别的页面切回来 popup 里面就会显示开关开着但规则没装上，
> 请关闭再开启一次，可问题是播放已经成功的被接管了，不用再重新开关一次」

`ruleCount` 读到 0 有至少两种情况不代表故障：

| 情况 | 为什么 0 不代表坏 |
| --- | --- |
| 切回标签页的瞬间 | 标签页规则随 `page/activate` 异步重建，popup 恰好在这个窗口打开 |
| 番剧页 | `countPathRules()` 只数 `kind === 'path'` 的**全局**规则，而番剧页生效的是**标签页规则**（`tabIds`） |

而「取流成功了」这个事实比规则计数硬得多 —— 规则真没装，播放账号的 4K 根本取不回来。
**用户能播 4K 却被告知"规则没装上"，会让用户去修一个没坏的东西。**

现在 `ruleCount: 0` 直接落到「已接管」；`PopupState` 里的 `'inconsistent'` 枚举值仍保留
（避免类型层大改），但 `describePopup()` **不再返回它**。`ruleCount` 仍回传给诊断页 ——
那里才是看"规则到底几条"的地方。

> 📌 **所以「popup 不再提示规则异常」是有意的，不是漏了。**
> 真要看规则，去 options 的「诊断」分区。

Options 是全屏标签页，承担全部"复杂操作"。**分三块**，用左侧导航 + 右侧内容（≥900px 时）或纵向滚动（窄屏）。

> 前者与 popup §2.3 是同一份数据，后者测不准、退化成静态清单。
> 理由见 [ADR 0016](./decisions/0016-drop-quality-report-page.md)。
>
> 现状（2026-10-27）：**账号页、显示页、诊断页全部完成**，含白名单版本行。
> 原独立的自检页已并入诊断分区（逐行比对 16 行全同后才删的）。

### 4.1 账号

> ✅ **已实现**：`entrypoints/options/sections/account.tsx`。
>
> - 主账号卡片（只读）：昵称 + mid，来自**当前视频页**的页面数据
>   （`__INITIAL_STATE__.user` + `DedeUserID`）。没开视频页时如实说"打开任意视频页后可见"，
>   **不发 nav 去猜**（决策 4）
> - 播放账号卡片：昵称 / mid / 会员类型 / 到期日 / 最近校验时间 + 「重新登录」「退出播放账号」
> - 退出是**两步确认**（不用 `confirm`，见 §7 反模式）
> - 扫码后轮询 `account/summary`（3 秒一次，最多 3 分钟）——
>   登录窗口在无痕分区，那里是另一个 background 实例，`storage.local` 是唯一可靠通道
>
> ⚠️ **「凭据年龄」没做**：vault 里没存 `savedAt`，现在只有"最近校验时间"。
> 要做需要给 `Credential` 加时间戳并迁移已有凭据，收益不大，先留空。

**三条补充约束**：

- **必须在 InPrivate 分区里登录**（`chrome.windows.create({ incognito: true })`），
  否则会覆盖主账号登录态（[ADR 0012](./decisions/0012-isolated-window-login.md)）。窗口尺寸见 `src/background/login-window.ts`
- **v1 只支持单个播放账号**（`core/vault` 的 `Credential` 是单数）。多账号 profile 推迟到 v1.5，
  理由见 [04-project-structure.md](./04-project-structure.md) §6「v1 只支持单个播放账号」
- 二维码用 **canvas 本地渲染**，不用远程图片 —— 避免把登录态泄露给第三方

扫码窗口内的状态机：等待扫码 → 已扫码待确认 → 成功 / 过期（可刷新）；
成功后窗口自动关闭并开启代理，popup 的状态胶囊变为「已接管」。

### 4.2 诊断

> ✅ **已实现**：`entrypoints/options/sections/diagnostics.tsx`，
> 取数逻辑在 `platform/diagnostics/collect.ts`。
> 原来的独立自检页（`entrypoints/diagnostics/`）已于同日删除 ——
> 删之前做过逐行比对（16 行事实全同），不是凭感觉删的。
>
> | 块 | 内容 |

> | 自检信息 | InPrivate 权限 / 窗口与分区 / 凭据 / 总开关 / DNR 规则 / 当前页取流数据 / 白名单版本 |

> | 诊断日志 | 最近 30 条，带实例 ID（`split` 下普通/无痕是两个 SW） |
> | 导出 | 下载 JSON（Blob + `<a download>`，**不申请 `downloads` 权限**），**不含任何凭据** |
>
> **白名单版本怎么显示（2026-10-26 定）**：
>
> ```
> 代理路径白名单   r3 · 核对于 2026-10-28
> ```
>
> - `ROUTES_REVISION`（整数，**只在路径字符串或 `enabled` 开关变化时 +1**，改注释不算）
> - `ROUTES_CHECKED_AT`（人工核对 B站 前端的日期）

>   白名单一年不用动，那个颜色会一直亮着 —— **假警报会训练用户忽略它**
> - 真正的报警**按证据**：最近 1 小时有取流失败时，才补一行
>   「白名单是否过期：最近 N 次取流失败 —— 如果刷新后仍持续，可能是接口路径变了」
>
> **没做的一项，是有意的**：**失败原因分布** —— 我们现在**根本不采集 playurl 业务码**
> （`summarizePlayurl` 在 `!json.data` 时就返回 null，`-412` 这类失败连原因都看不到）。
> 要做得先补一条数据链路；而且 playurl 每次加载只调一次，样本量下画饼图看到的是噪声。

### 4.3 显示

> **2026-10-26 新增第五分区**（当时是五分区方案；后来砍到三分区，它保留为「显示」）。
> 原稿只有四块，角标开关无处安放（`02` §5 只写"设置里可关闭"）。
>
> ✅ **已实现**：`entrypoints/options/sections/display.tsx` + `platform/storage/ui-prefs-store.ts`。
> 开关存 `storage.local`，content script 监听 `storage.onChanged`，**保存后立刻生效、不用刷新**。

**优先级低**，只有两行，不加任何新组件：

| 项 | 控件 | 默认 | 说明 |
| --- | --- | --- | --- |
| 页内角标 | 开关 | 开 | 关掉后**立即消失**（content script 监听 `storage.onChanged` 重画），不用刷新 |
| 深色模式 | 只读文案 | 跟随系统 | 由 `tokens.css` 的 `prefers-color-scheme` 决定，暂不提供手动切换 |

**为什么单开一页而不是塞进「账号」或「诊断」**：

- 塞「账号」页 → 用户会以为角标跟账号绑定（"换个号就不显示了？"），而它其实跟账号无关
- 塞「诊断」页 → 用户会以为它是排查工具（"排查完就该关掉"），而它是常驻的显示偏好
- options 的分区是按"这一页回答什么问题"切的，角标既不是账号信息、也不是体检数据、更不是排查手段

**代价**：这一页目前内容极少，看起来"空"。接受这个空 —— 角标位置/大小/显示时长这类设置迟早要加，
有独立分区就不用每次重排导航。

## 5. 页内注入（content script）

只做一件事：在播放器控制栏区域加一个**极小的角标**，不改变原有布局。

```
播放器右下角： [ ◈ 4K·Hi-Res ]  ← 12px 字号，半透明
```

- **点击**展开小浮层，**鼠标移开**自动收起（不占用 hover 态，避免误触）
- 浮层内容 = **实测值**，不是"能力清单"：

  ```
  取流身份：播放账号 ｜ 当前画面 2160p ｜ 60fps ｜ 视频 HEVC(hvc1) ｜ 音频 FLAC
  ```

  > ⚠️ 这里**故意不写「已解锁 4K/1080P60/Hi-Res」**。
  > "解锁"是能力声明，"当前画面"是事实陈述。用户看到「已解锁 4K」而实际在 1080P，
  > 会以为功能坏了——这正是本项目「不许谎报」原则要避免的。
  > 能力清单放在 popup 的「当前页解锁画质」区（§2.3），那里有接口数据支撑。

- 设置里可关闭（载体是 options 页的**「显示」分区**，见本文件 §4.3；已实现，保存后立即生效）
- **不要**做任何遮挡播放器的浮层，不要自动弹出任何提示

### 实现要点（2026-10-26 落地）

| 项 | 做法 | 为什么 |
| --- | --- | --- |
| 隔离 | `attachShadow({ mode: 'closed' })` | 页面脚本拿不到 `shadowRoot`，无法篡改 |
| 渲染 | 原生 DOM + `textContent` | 20 行 DOM，上框架收益为零；用 `textContent` 而非 `innerHTML`，杜绝注入面 |
| 样式 | `import tokensCss from 'tokens.css?raw'` 塞进 shadow root 的 `<style>` | **CSS 变量不穿透 shadow 边界**，必须把规则文本塞进去 |
| 根选择器 | `tokens.css` 用 `:host, :root` | `:root` 不匹配 shadow tree，只写它会导致角标样式全失效 |
| 数据来源 | **只用实测值**：`videoHeight` + SourceBuffer 实际 mime | `accept_quality` 在未登录时就返回含 8K 的数组，拿它展示等于骗人 |

**三条"不许谎报"规则**（代码在 `src/content/isolated/badge-content.ts`，有单测锁住）：

1. 没在代理 → 角标完全不显示
2. 代理了但还没开播 → 只说「已接管」，**绝不猜画质**
3. 编码没确认 → 不写「Hi-Res」/「60fps」，未知一律省略

这是"存在感"与"侵入感"的平衡点。用户如果不想看到，可以关掉；想确认时，不用点扩展图标。

## 6. 视觉规范

| 项 | 值 |
|---|---|
| 主色 | 信息蓝（`#378ADD` / 浅底 `#E6F1FB`）区别于 B 站的粉色，避免与站内 UI 混淆 |
| 危险色 | 红（`#E24B4A`）仅用于凭据失效 |
| 警告色 | 琥珀（`#EF9F27`）仅用于降级 |

| 字体 | 系统字体栈，不引入 webfont（popup 加载延迟敏感） |
| 图标 | 内联 SVG，不用 emoji（跨平台渲染不一致） |

**B 站品牌色不要用**。用粉色会让人以为是 B 站官方插件，出了问题容易被误认为官方行为。信息蓝是中性、技术感、不占位。

## 7. 交互反模式（明确禁止）

| 禁止 | 原因 |
|---|---|
| popup 内放二维码 | 失焦即关闭，扫码必失败 |
| popup 内做长任务（体检、批量取流） | 关闭即中断，用户以为没生效 |
| 用 `alert` / `confirm` | 阻塞 SW，且在 popup 里表现异常 |
| badge 显示数字 | badge 空间只够 4 字符，数字无法表达状态；改用颜色（绿/红/无） |
| 首次安装自动打开 options 页 | 打断用户当前浏览；改为图标上挂一个引导 badge |
| 权限一次性全要 | 应分阶段申请：先 `storage`，用户配好播放账号后再请求 `declarativeNetRequest`。**现状：未做**（manifest 一次性声明，见 `wxt.config.ts`），属于"知道但没实现"的项 |
| 伪装会员标识默认开 | 制造误解，反噬信誉（v1 已整体移除，见 Q12） |
| 把"开关关闭"表达成功能失败 | 用户主动关的，不该报警 |

## 8. 首次安装引导（onboarding）

三步，但**不在安装时强制**，而是"用户第一次打开视频页时"触发：

1. 图标 badge 显示一个小圆点（非数字）
2. 用户点开 → popup 显示"未配置"空状态
3. 点"扫码登录"→ 开独立窗口 → 扫码 → 成功 → 窗口关闭 → 回到视频页自动刷新一次

**为什么不用安装后自动开 options**：Chrome 商店审核不欢迎强制跳转，且用户此时没有上下文（不知道为什么要登录）。等到他看到视频页画质不行，动机最强。

> ⚠️ **登录入口的唯一位置是 popup。** P2 加了 `default_popup` 之后
> `chrome.action.onClicked` **不再触发**（Chrome 的规则：有 popup 时点图标只开 popup），
> 所以早期"点图标直接开登录窗口"的做法已废弃。handler 见
> `entrypoints/background.ts` 的 `handleLoginOpen()`。

## 10. 一句话总结

**Popup 只回答一个问题："现在生效了吗？"**
所有需要用户"做事"的地方，都搬到 options 页和独立窗口。
所有异常状态都必须给出**归因 + 后果 + 一个明确动作**，三者缺一不可。

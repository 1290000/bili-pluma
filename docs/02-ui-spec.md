# Pluma UI 设计规范（B站双账号画质助手）

> 项目名 **Pluma** / 仓库名 `bili-pluma`。界面中品牌名统一显示为 **Pluma**。
> 形态：纯 MV3 扩展（见 [01-architecture.md](./01-architecture.md)）
> **技术实现**：popup / options / login window 用 **Preact**；页内角标用**原生 DOM + Shadow DOM**；样式用**原生 CSS 变量**。
> 完整技术选型与目录位置见 [04-project-structure.md](./04-project-structure.md) §〇。
> 范围：popup / options / 页内注入 / 首次引导 四类界面

---

## 0. 一条铁律

**Popup 是"查看器"，不是"操作台"。**

用户点开 popup 的心理预期是 2 秒内确认"现在有没有生效"。如果界面需要他读、需要他点、需要他思考，设计就是失败的。

判断标准：**popup 上的每一个元素，都必须能回答"我现在应该担心吗"这个唯一问题。** 不能回答的，全部移出 popup。

---

## 1. 尺寸与技术约束（先看这个，否则设计白做）

| 约束 | 数值 | 影响 |
|---|---|---|
| Popup 最大宽 | 800px | 但实际应控制在 **360–400px**，更宽会显得空 |
| Popup 最大高 | 600px | 超过出现滚动条，体验急剧下降 |
| **Popup 失焦即关闭** | — | **致命约束**：扫码登录、长任务、需要切窗口的流程都不能放这里 |
| Popup 无固定高度 | 内容撑开 | 不同状态高度不一致会导致"抖动"，需给主容器设 `min-height` |
| Popup 不能调 `window.close()` 外的窗口控制 | — | 无法做"最小化到托盘" |
| Service Worker | 30s 无事件休眠 | 长连接、长任务需 `chrome.alarms` 续命 |
| Options 页 | 全屏标签页 | 唯一能放复杂 UI 的地方 |

**推论**：扫码登录必须开独立窗口或 options 页。绝不能在 popup 里放二维码——用户拿手机扫的时候 popup 已经关了。

## 2. Popup 设计

### 2.1 信息架构（自上而下，按重要性递减）

```
┌─────────────────────────────────────┐
│ 1. 状态条  品牌 + 接管状态 + 健康点   │  ← 20% 注意力，2 秒内可读完
├─────────────────────────────────────┤
│ 2. 当前页解锁画质（含对比）           │  ← 40% 注意力，核心价值证明
├─────────────────────────────────────┤
│ 3. 双账号卡片 A / B                  │  ← 25% 注意力，信任建立
├─────────────────────────────────────┤
│ 4. 快捷开关（自动接管取流）            │  ← 10%
├─────────────────────────────────────┤
│ 5. 底部操作（体检 / 切换 / 设置）      │  ← 5%
└─────────────────────────────────────┘
总高控制在 460–520px
```

### 2.2 状态条（最关键的 20px）

左侧：品牌名 + 状态胶囊。右侧：绿点 + 一句话。

状态胶囊共 5 种，必须互斥且唯一：

| 胶囊文案 | 颜色 | 触发条件 | 右侧文字 |
|---|---|---|---|
| 已接管 | success | 有播放账号 + 开关开 + 当前页命中白名单 | 代理正常 |
| 未生效 | 中性 | 有播放账号 + 但当前页不是视频页 | 等待视频页 |
| 未配置 | 中性 | 无播放账号 | 点击登录 |
| 凭据失效 | danger | 播放账号 nav 返回 -101 | 需重新扫码 |
| 已降级 | warning | 有播放账号但代理连续失败 | 查看诊断 |

**设计要点**：
- 胶囊文案必须短（2–3 字），因为用户不会读长句。
- **不要用"开启/关闭"这类描述开关状态的词**，要用"已接管/未生效"这类描述**结果**的词。用户关心结果。
- 绿点只在"已接管"和"代理正常"时显示，其他状态用对应色点或隐藏。

### 2.3 当前页解锁画质（核心价值区）

> ⚠️ **本节尚未实现，顺延到 P3（2026-10-26 核验）**。
> 它需要 `core/playinfo/parse.ts` / `rank.ts` 解析 `accept_quality` 并做主/副账号对比，
> 那套模块是 P3 的核心。当前 popup 只有状态条 + 开关，回答不了"解锁了什么"。
> 清单见 [04-project-structure.md](./04-project-structure.md) §6「P2 顺延到 P3 的四项」。

这是整个 popup 唯一不能省的部分。

```
当前页面 · BV1xx411c7mD
┌───────────────────────────────────┐
│ 已解锁          主账号仅可用 1080P  │
│ [4K] [1080P60] [HDR] [Hi-Res]     │
└───────────────────────────────────┘
```

**三个设计决策**：

1. **必须有对比**。"主账号仅可用 1080P"这行小字不是装饰，它是价值锚点。没有对比，用户感受不到这个插件做了什么。
2. **徽章用"已解锁"而非"可用"**。语义差异：前者隐含"因为插件才有的"，后者中性。
3. **超出宽度换行，不横向滚动**。最多展示 6 个徽章，超出的收成 `+2`。

**数据来源**：content script 在播放页拿到当前 `video` 元素实际生效的 `qn`/codecid，以及本次 playurl 响应的 `accept_quality`，report 给 popup。**不要重新请求**，用已有数据。若当前页不是视频页，此区替换为一句话"打开任意视频页查看效果"。

**边界情况**：
- 视频本身最高只有 1080P → 显示"此视频最高 1080P（源限制）"，避免用户以为是插件没生效。
- 版权番剧需付费 → 显示"N 集需大会员或购买"，给出具体数字。

### 2.4 双账号卡片（信任建立区）

> ⚠️ **当前是简化实现**（2026-10-26 核验）：popup 只渲染**播放账号**一行摘要
> （`uname` + 会员信息 + 「仅取流」标签），**没有主账号卡片**，也没有两侧对比。
> 完整版依赖 §2.3 的数据（"主账号仅可用 1080P"），随 §2.3 一起进 P3。

两个卡片的**视觉层级必须刻意拉开**：

| | 主账号 A | 播放账号 B |
|---|---|---|
| 头像底色 | 灰（`background-secondary`） | 信息色（`background-info`） |
| 副标题 | `收藏 · 点赞 · 评论 · 历史` | `仅取流 · 到期 YYYY-MM-DD` |
| 右侧标签 | LV6 等真实等级（灰） | 会员类型（信息色） |
| 可点击 | 否 | 是（打开切换菜单） |

**为什么这样设计**：用户的潜在恐惧是"我的号会不会被盗/被切走"。视觉上要让 B 看起来像一个**受控的工具**，而不是另一个"活跃账号"。所以 B 的副标题是"仅取流"，这是在明确职责边界。A 的副标题列出四项社交行为，是在确认"这些还是你的"。

**B 卡片必须显示到期日**，因为它会驱动续费决策，也是"为什么突然失效"的最常见答案。

### 2.5 快捷开关

**v1 只放一个开关。**

| 开关 | 副标题 | 默认 |
|---|---|---|
| 自动接管取流 | 无（主功能，顾名思义） | 开 |

**"伪装会员标识"已在 Q12 决策中移除（v1 不做）**。原因见待确认清单 Q12：收益小（只是界面顺眼）、有风控风险、有伦理问题（用户误以为自己有会员）。

好处是 popup 更简洁——只有一个开关时，用户不需要做任何选择，开箱即用。

> 如果未来某个版本要重新引入，必须是**显式高级选项、默认关闭、warning 色标注**，且文案写明"仅修改界面显示，不改变账号实际权益"。

### 2.6 底部操作

> ⚠️ **本节整体顺延到 P3（2026-10-26）**。三个按钮**全部**指向 options 页，
> 而 options 页是 P3 的第一项——页不存在时放按钮就是死链。
> 理由见 [04-project-structure.md](./04-project-structure.md) §6「P2 顺延到 P3 的四项」。

三个按钮，三档视觉权重：

| 按钮 | 权重 | 行为 |
|---|---|---|
| 画质体检 | 主要 | 在 options 页打开对比表 |
| 切换播放账号 | 中等 | 在当前位置展开下拉（不跳转，避免丢上下文） |
| 设置 | 次要（图标或弱化文字） | 打开 options 页 |

**"画质体检"放在第一个**，因为它是这个项目最好的"功能自证"——用户点一下就能看到主/副账号的 `accept_quality` 差异表，比任何说明文字都有效。

## 3. Popup 的状态（实现为 7 种）

只设计正常状态是新手常见错误。**原设计 5 种，实装时发现必须再加 2 种**——
「已停用」和「异常」不是细节，而是用户最容易遇到的两种情况。

> **以 `src/core/ui/popup-state.ts` 的 `PopupState` 为准**，下表是文档与代码的映射。
> 改状态时两边都要动，否则又会出现"规范说 5 种、代码有 7 个"这种漂移。

| 代码 `state` | 状态胶囊 | 对应本节 |
| --- | --- | --- |
| `not-configured` | 未配置 | 状态 1 |
| `active` | 已接管 | 状态 2 |
| `credential-missing` / `expired` | 凭据失效 | 状态 3 |
| `degraded` | 已降级 | 状态 4 |
| `stopped` | 已停用 | **状态 6（实现新增）** |
| `inconsistent` | 异常 | **状态 7（实现新增）** |
| —— | —— | 状态 5「非视频页」**尚未实现** |

### 状态 1：未配置（首次使用）
- 状态胶囊：未配置
- 主体：居中空状态图示 + 一句话 + 主按钮"扫码登录播放账号"
- 底部小字：**"主账号无需配置，自动读取当前浏览器登录"** ← 这句极其重要，消除"我要不要把主账号密码也给出去"的疑虑

### 状态 2：正常接管
见 §2

### 状态 3：凭据失效
- 状态胶囊：凭据失效（danger）
- 顶部 danger 边框卡片：标题"播放账号登录已过期" + 说明"B 站在别处登出了此账号，或凭据已超 180 天。当前已回退为主账号画质。"
- 账号摘要行："大会员号 · 3 天前失效"
- 主按钮：重新扫码（danger 色描边）

**关键**：必须给出**归因**（"在别处登出"）和**后果**（"已回退为主账号画质"）。否则用户会反复点重试。

### 状态 4：已降级（代理失败但可播）
- 状态胶囊：已降级（warning）
- 卡片：标题"取流接口已被代理，但返回异常" + 错误码与含义（如 `-412 风控`）
- 一句话安抚：**"已自动回退主账号身份，视频可正常播放。"**
- **10 分钟成功率条形图**（8–12 根柱，绿/黄/红三色）
- 按钮：查看诊断日志

**这个成功率图是纯扩展形态下最有价值的诊断组件**。用户说"没效果"时，这张图是唯一能立刻区分"没配好"和"被风控"的证据。实现上只需在 SW 里维护一个长度 12 的环形数组。

### 状态 5：非视频页（⚠️ 尚未实现）

- 状态胶囊：未生效
- 主体：一句话"当前页面不是视频页" + 可选"最近观看的三个视频"快捷入口

> 代码里**没有**对应的 `state`——popup 目前不判断当前标签页是不是视频页。
> 补的时候要在 `PopupState` 加一个值，并同步本节开头的映射表。

### 状态 6：已停用（用户关掉了总开关）

- 状态胶囊：已停用（neutral）
- 一句话："当前使用主账号画质"

**必须排在「凭据失效」之前。** 用户自己把开关关掉时，那是当下最能解释"为什么没 4K"的事实；
如果先报"凭据失效"，用户会去重扫一个本来好用的号，扫完发现还是没画质——因为开关压根没开。
这是纯粹的误导。

**顺序原则**：能解释当前结果的状态优先，与用户操作相关的优先于与后台校验相关的。

### 状态 7：异常（开关开着但规则没装上）

- 状态胶囊：异常（warn）
- 一句话："开关开着但规则没装上，请关闭再开启一次"

这是"配置不一致"：代理开关是开的，但 DNR 规则不在（SW 重启后自愈失败、或规则被外部清掉）。
给的动作是**关一次再开**，不是重扫。

## 4. Options 页设计

Options 是全屏标签页，承担全部"复杂操作"。分四块，用左侧导航 + 右侧内容（≥900px 时）或纵向滚动（窄屏）。

### 4.1 账号
- 两个大卡片，主账号（只读展示，来源是浏览器登录态）与播放账号（可登录、可退出）
- **v1 只支持单个播放账号**（`core/vault` 的 `Credential` 是单数）。多账号 profile 推迟到 v1.5，
  理由见 [04-project-structure.md](./04-project-structure.md) §6「v1 只支持单个播放账号」
- 扫码登录：**点按钮后 `chrome.windows.create({url, type:'popup', width: 420, height: 600, incognito: true})` 开隔离窗口**
  - **必须在 InPrivate 分区里登录**，否则会覆盖主账号登录态（[ADR 0012](./decisions/0012-isolated-window-login.md)）
  - 窗口内展示二维码（用 canvas 渲染，不用远程图片，避免隐私泄露）
  - 状态机：等待扫码 → 已扫码待确认 → 成功 / 过期（可刷新）
  - 成功后窗口自动关闭并开启代理，popup 的状态胶囊变为「已接管」
- 播放账号卡片显示：昵称、mid、会员类型、到期日、最近校验时间、凭据年龄

### 4.2 画质体检（核心卖点页）
一张对比表：

| 项目 | 主账号 | 播放账号 | 差值 |
|---|---|---|---|
| 最高清晰度 | 1080P | 4K | 2 档 |
| 最高帧率 | 30 | 60 | — |
| HDR | 不支持 | 支持 | — |
| 杜比视界 | 不支持 | 支持 | — |
| Hi-Res | 不支持 | 支持 | — |
| 杜比全景声 | 不支持 | 支持 | — |

数据来源：对当前 BV（或用户输入的 BV/ep）**分别**用两套身份调一次 playurl，对比 `dash` 各轨存在性。
**判据只能用 `dash.video[].height` / `dash.flac` / `dash.dolby`，不能用 `accept_quality`** ——
实测未登录时它就返回含 8K 的完整数组，不代表这个身份能拿到（`poc/verify/RESULT.md` §四）。

**这个页面的价值**：它是唯一能"用数据说服用户"的地方。README 里放它的截图，转化率会明显不同。

### 4.3 音质与环境自检
因为杜比/Hi-Res 依赖用户环境，必须有这个面板：

| 检查项 | 方法 | 失败时引导 |
|---|---|---|
| FLAC 解码 | `new Audio().canPlayType('audio/flac')` 或 MediaCapabilities | 换 Edge/新版 Chrome |
| EC-3 解码器 | Store 包 `9nvjqjbdkn97` 是否安装 | 一键打开 Store 链接 |
| Media Foundation | `chrome://flags` 相关项状态 | 给截图级操作指引 |
| 系统空间音频 | 无法直接读，给操作路径 | Windows 设置 → 声音 → 空间音频 |
| 输出设备格式 | 同上 | 建议设为"杜比全景声家庭影院" |

**注意**：`chrome://flags` 扩展读不到，只能引导用户自查。文案要具体到"在地址栏输入 xxx，搜索 yyy，选 Enabled，重启浏览器"。

### 4.4 诊断

- 路径命中日志（最近 200 条，脱敏：cookie 一律显示为 `SESSDATA=***`）
- 失败原因分布（饼图或堆叠条）
- 一键导出诊断包（**默认不含任何凭据**，只含错误码、时间、路径、版本）
- 远程配置状态（白名单版本号、是否已过期）

## 5. 页内注入（content script）

只做一件事：在播放器控制栏区域加一个**极小的角标**，不改变原有布局。

```
播放器右下角： [ ◈ 4K·Hi-Res ]  ← 12px 字号，半透明
```

- **点击**展开小浮层，**鼠标移开**自动收起（不占用 hover 态，避免误触）
- 浮层内容 = **实测值**，不是"能力清单"：

  ```
  取流身份：播放账号 ｜ 当前画面 2160p ｜ 60fps ｜ 视频 HEVC(hvc1) ｜ 音频 FLAC
  ```

  > ⚠️ 这里**故意不写「已解锁 4K/1080P60/Hi-Res」**。
  > "解锁"是能力声明，"当前画面"是事实陈述。用户看到「已解锁 4K」而实际在 1080P，
  > 会以为功能坏了——这正是本项目「不许谎报」原则要避免的。
  > 能力清单放在 popup 的「当前页解锁画质」区（§2.3），那里有接口数据支撑。

- 设置里可关闭（⚠️ **开关顺延到 P3**，载体是 options 页；当前只能靠总开关隐藏，见 [04-project-structure.md](./04-project-structure.md) §6「P2 顺延到 P3 的四项」）
- **不要**做任何遮挡播放器的浮层，不要自动弹出任何提示

### 实现要点（2026-10-26 落地）

| 项 | 做法 | 为什么 |
| --- | --- | --- |
| 隔离 | `attachShadow({ mode: 'closed' })` | 页面脚本拿不到 `shadowRoot`，无法篡改 |
| 渲染 | 原生 DOM + `textContent` | 20 行 DOM，上框架收益为零；用 `textContent` 而非 `innerHTML`，杜绝注入面 |
| 样式 | `import tokensCss from 'tokens.css?raw'` 塞进 shadow root 的 `<style>` | **CSS 变量不穿透 shadow 边界**，必须把规则文本塞进去 |
| 根选择器 | `tokens.css` 用 `:host, :root` | `:root` 不匹配 shadow tree，只写它会导致角标样式全失效 |
| 数据来源 | **只用实测值**：`videoHeight` + SourceBuffer 实际 mime | `accept_quality` 在未登录时就返回含 8K 的数组，拿它展示等于骗人 |

**三条"不许谎报"规则**（代码在 `src/content/isolated/badge-content.ts`，有单测锁住）：

1. 没在代理 → 角标完全不显示
2. 代理了但还没开播 → 只说「已接管」，**绝不猜画质**
3. 编码没确认 → 不写「Hi-Res」/「60fps」，未知一律省略

这是"存在感"与"侵入感"的平衡点。用户如果不想看到，可以关掉；想确认时，不用点扩展图标。

## 6. 视觉规范

| 项 | 值 |
|---|---|
| 主色 | 信息蓝（`#378ADD` / 浅底 `#E6F1FB`）区别于 B 站的粉色，避免与站内 UI 混淆 |
| 危险色 | 红（`#E24B4A`）仅用于凭据失效 |
| 警告色 | 琥珀（`#EF9F27`）仅用于降级 |
| 字号 | 标题 14–15px / 正文 13px / 辅助 11px，**不出现 11px 以下** |
| 圆角 | 卡片 12px，控件 8px，徽章 4px |
| 边框 | 0.5px，`rgba(0,0,0,.15)` |
| 字体 | 系统字体栈，不引入 webfont（popup 加载延迟敏感） |
| 图标 | 内联 SVG，不用 emoji（跨平台渲染不一致） |
| 深色模式 | 必须支持，用 `prefers-color-scheme` + CSS 变量 |

**B 站品牌色不要用**。用粉色会让人以为是 B 站官方插件，出了问题容易被误认为官方行为。信息蓝是中性、技术感、不占位。

## 7. 交互反模式（明确禁止）

| 禁止 | 原因 |
|---|---|
| popup 内放二维码 | 失焦即关闭，扫码必失败 |
| popup 内做长任务（体检、批量取流） | 关闭即中断，用户以为没生效 |
| 用 `alert` / `confirm` | 阻塞 SW，且在 popup 里表现异常 |
| badge 显示数字 | badge 空间只够 4 字符，数字无法表达状态；改用颜色（绿/红/无） |
| 首次安装自动打开 options 页 | 打断用户当前浏览；改为图标上挂一个引导 badge |
| 权限一次性全要 | 应分阶段申请：先 `storage`+`alarms`，用户配好播放账号后再请求 `declarativeNetRequest` |
| 伪装会员标识默认开 | 制造误解，反噬信誉（v1 已整体移除，见 Q12） |
| 把"开关关闭"表达成功能失败 | 用户主动关的，不该报警 |

## 8. 首次安装引导（onboarding）

三步，但**不在安装时强制**，而是"用户第一次打开视频页时"触发：

1. 图标 badge 显示一个小圆点（非数字）
2. 用户点开 → popup 显示"未配置"空状态
3. 点"扫码登录"→ 开独立窗口 → 扫码 → 成功 → 窗口关闭 → 回到视频页自动刷新一次

**为什么不用安装后自动开 options**：Chrome 商店审核不欢迎强制跳转，且用户此时没有上下文（不知道为什么要登录）。等到他看到视频页画质不行，动机最强。

> ⚠️ **登录入口的唯一位置是 popup。** P2 加了 `default_popup` 之后
> `chrome.action.onClicked` **不再触发**（Chrome 的规则：有 popup 时点图标只开 popup），
> 所以早期"点图标直接开登录窗口"的做法已废弃。handler 见
> `entrypoints/background.ts` 的 `handleLoginOpen()`。

## 10. 一句话总结

**Popup 只回答一个问题："现在生效了吗？"**
所有需要用户"做事"的地方，都搬到 options 页和独立窗口。
所有异常状态都必须给出**归因 + 后果 + 一个明确动作**，三者缺一不可。

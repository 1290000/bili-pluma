### 2.4 G6 调研结论（2026-10-29，只读）

- **产物**：`-with-source.zip` 根加 `BUILD.md`——版本 / commit / 工作区状态 / 构建命令 / Node / wxt+lockfile 哈希 / `extension/**` 逐文件 sha256 表；由 `package.mjs` 在 `// ── 6. 打源码版` 节、`zipDir(srcName)` 之前写入 `stagingSrc/`
- **自指悖论**：with-source 自身哈希写进 `dist/release-notes.md` 的 `### 校验和`（两个 zip 都落盘后）
- **`package.mjs` 加三条硬失败**：脏工作区 / 无 git / `.output` 比源码旧
- **`check-artifact.mjs` 加 `-with-source` 分支**（复用现有 zip 解析，不新增 `verify` 步骤）
- **先决条件（R1）**：先实测"同 commit 两次 build 字节一致"与"Node 22 vs 24 一致"；不一致则降级为逐文件哈希 + 差异解释，或钉死 Node/wxt
- **流程变更（R2）**：clean-tree 门要求先提交 CHANGELOG/版本号再打包；`releasing.md` 的"打包 → 写 CHANGELOG"顺序需调整
- **验收**：解压后按 BUILD.md 重建，哈希表 `diff` 为空；反例 = 改 hash / 删 BUILD.md / 版本改 9.9.9 / 塞 `安装说明.txt` / 脏树打包

### 2.5 R1 可复现性（2026-10-30 实测）

- 方法：整仓复制到 `.tmp/r1/repo`（`node_modules` 用 junction，排除 `.output`/`dist`），在副本里 `node node_modules/wxt/bin/wxt.mjs build`
- **同 commit、Node 24.21.0 两次 build**：`chrome-mv3` **24 个文件 sha256 逐字节一致**
- **Node 22.22.2 vs Node 24.21.0**：**24 个文件逐字节一致**
- 结论：BUILD.md 的逐文件哈希方案可行；凭证必须记录 Node 版本、wxt 版本（0.21.4）、`pnpm-lock.yaml` 哈希
- 边界：单机 / Windows x64；跨机器、跨 wxt 版本未测。比对对象是 `extension/**` 逐文件，不是 zip 字节（zip 含时间戳）

### 2.6 1.1.0 真机回归（2026-10-30，新构建）

| 场景 | 判据 | 结果 |
| --- | --- | --- |
| 完整集 `ep3854818` | `dur 1167` / 3840×2160 / `cacheRejectedTruncated=false` | ✅ |
| SPA `ep3854818→3854819` | `swapCount 1` / `swapLastMaxH 2160` / `dur 1146` / 4K | ✅ |
| PV `ep4292430` | `dur 48.76` / 1080P / `lastStage=boot`（SSR 完整，跳过取流） | ✅ |

- **未覆盖**：playback 账号**无权益**的 `truncated` 分支（真机未找到样本）；G1 的 `fetch-truncated` 分支真机未触发。

# Pluma 1.0.1 / 1.1.0 方案（草案）

> 版本：v0（草案，范围待用户确认）
> 日期：2026-10-29
> 依据：`.workbuddy-ai/HANDOFF.md` §4 / `docs/03-open-questions.md` §0 / `docs/04-project-structure.md` §6 / `docs/guides/versioning.md`

## 0. 一句话结论

1.0.0 之后先做 **1.0.1 质量补丁**（只修 1.0.0 暴露的缺口，不加功能），再做 **1.1.0**（v1.5 预留项）。
超出双账号的扩展另起架构评审，不与 1.0.x 混排。

## 1. 1.0.0 已知缺口（不许写成"已验证"）

### 1.1 未验证

| 项 | 状态 |
| --- | --- |
| popup / options 的实际渲染 | `chrome-extension://` 被 bsk 沙箱拒绝，只能人眼 |
| 单集 > 116 分钟任意拖动 | 机制上正常，**从未实测** |
| HDR / 杜比视界 | 浏览器 API 不可靠，只能肉眼对比 |
| `incognito:"split"` 下 `localStorage` 一致性 | ADR 0028 已记为已知弱点 |

### 1.2 代码缺口

| # | 位置 | 问题 | 优先级 |
| --- | --- | --- | --- |
| G1 | `src/core/playinfo/pgc-merge.ts:138` `hasPlayableStream` | 只判"有没有流"，不判"够不够长"——整条链第一个漏点 | P1 |
| G2 | `src/content/main-world.js` 的 `cfg` 补注入 | 永远晚于 `createPlayer`（1450ms vs 400ms），这条路从未成功 | P2（只记录，不依赖） |
| G3 | `pgc-reload-plan` 护栏 | `MAX_RELOAD_ATTEMPTS=1` + 10min TTL 跨轮次残留 | P2（需 ADR） |
| G4 | `poc/q2-dnr-concurrency` S1 | `pool-random-id` r3 末 4 个确定性缺失，原因未查清 | P2（纯排查） |
| G5 | `entrypoints/content.ts` `hello` 分支 | `tellMainWorld(true)` + 异步补 `false` 短暂污染 `cfgEnabled` 观测 | P3 |
| G6 | `scripts/package.mjs` | `-with-source.zip` 无构建命令/产物哈希，不满足 ADR 0018 原意 | P2（1.0.1 首选） |

## 2. 1.0.1 范围（建议）

### 2.1 In scope

| 顺序 | 项 | 验收判据 | 回归 |
| --- | --- | --- | --- |
| 1 | **G6** 构建凭证 | 解压 `-with-source.zip` 能按文档重建并与产物 sha256 比对 | `verify` 全绿 |
| 2 | **G1** 语义 + 实现 | 先定"够长"判据（`timelength` / dash duration / 缓存完整性）；补反例 | `main-world` 测试 + 真机 PGC 首次进入/切集 |
| 3 | **G4** 排查 | 给出 S1 r3 缺失的机理或明确"仍未知 + 不影响现行策略" | 只读分析，不改产品代码 |
| 4 | **G3**（可延后） | 单独 ADR 改 `MAX_RELOAD_ATTEMPTS` 语义；不满足就放 1.0.2 | 真机"第一次刷没成功"场景 |

### 2.2 Out of scope

- 新功能、v1.5 项、`main-world.js` 重构、超出双账号的能力
- 任何新增改写路径/主机（AGENTS.md §5.5：先改 ADR）

### 2.3 发布门禁

`verify` 13 项全绿；改 `dnr.ts` 则跑两个 DNR 脚本；改 `main-world.js` 则真机日志；每个修复附"改回去必须红"的反例。

## 0. 一句话结论

**0.9.0 的发行产物（`dist/pluma-0.9.0.zip`）与仓库源码严重脱节 —— 不是"少了 PGC"，是"少了整个主世界脚本与响应改写能力"。**
1.0.0 的首要目标**不是加功能，是让发布产物第一次等于源码**。在此基础上修 6 个 bug、补 3 条自动化守卫。

## 1.2 解包 `dist/pluma-0.9.0.zip` 的实测结果

> ⚠️ 本节被 `docs/guides/v1-acceptance-checklist.md` 引用（「旧结论不能证明新构建是对的」），**编号与结论不得改动**。

解包 0.9.0 发行 zip 逐项比对，得到两条推翻既有文档的结论：

1. **发行产物里没有 `main-world.js` 注入** → 会员字段改写、进度还原、PGC 三处改写**在发行版里全部不生效**。
2. **产物与源码不同源** → 源码里有的能力，用户装到的包里没有。

**教训（本项目此后一直沿用）**：任何"某功能是否生效"的结论，必须**在发行产物上**验，不能只看源码或开发态。

## 6.2 优先级判定规则

> ⚠️ 本节被 `src/platform/http/dnr.ts:74` 与两个单测文件引用（「§6.2 判据 1」），**编号与判据内容不得改动**。

用**二维矩阵**（影响面 × 可发现性），不靠"感觉严重"：

| | **用户能立刻察觉** | **用户察觉不到（静默）** |
| --- | --- | --- |
| **影响核心功能**（画质/身份/凭据） | 🔴 **P0** | 🔴 **P0** |
| **影响辅助功能**（UI/统计/提示） | 🟠 P1 | 🟡 P2 |
| **影响开发流程**（检查/文档/产物） | 🟠 P1 | 🟡 P2 |

**判定依据三条**：

1. **「静默失效」自动升级一级**。串号是「用错账号」（事后能发现），静默降级是「扩展没生效」（极难排查）。**能骗过用户的 bug 比报错的 bug 严重。**
2. **「界面说的和事实不一致」一律 P0/P1**。popup 显示「已停用」而实际还在代理，是「最坏的一类不一致」。
3. **「说不出判据的测试等于没写」**。任何标 P1 以上的修复，必须留下**可复跑的判据**（脚本或明确的真机操作步骤 + 期望值）。

## 0. 决策前置：五道闸（不解决不要动代码）

### 0.1 ⚠️ 唯一真正的硬阻塞：`host_permissions`

现在 manifest 只声明了 **`*://*.bilibili.com/*`**（`wxt.config.ts:85`）。
`live.bilibili.com` 的域名路径是 **`live.bilibili.com/<房间号>`** —— **不匹配** `*.bilibili.com/*`。

结论：**「删除直播水印」按现状一行代码都跑不起来**，content script 根本不会注入到直播页。
必须先做一次**权限扩面决策**：

| 方案 | 写法 | 代价 |
| --- | --- | --- |
| A（推荐） | `*://*.bilibili.com/*` + **`*://live.bilibili.com/*`** | 权限提示从"bilibili.com"变成"bilibili.com 和 live.bilibili.com"，用户可感知 |
| B | 收窄到 `*://*.bilibili.com/video/*` + `*/bangumi/play/*` + `*/` + `live.*/*` | 精确但难维护，`matches` 与 `host_permissions` 双份手工同步 |
| C | **往后的动态权限**：核心功能不扩，直播水印做成可选，首次启用时 `permissions.request()` | 不吓退只用画质的用户；但 `AGENTS.md` §7 禁"加检查项/加依赖"，**动态权限属于新增机制，必须用户点头** |

> 这是本次唯一会**改变用户可见权限提示**的改动，也是唯一无法靠代码内规避的。
> 建议 A；若想保画质用户的清爽体验，再叠加 C 的降级路径。

### 0.2 四道"翻案闸"（改了就是改决策，须用户明确点头）

| 事实 | Bilibili-Evolved（`the1812`） | Ghost-Downloader-3（`XiaoYouChR`） |
| --- | --- | --- |

| 附加条款范围 | **只约束"发布脚本完整内容"**（分发 `.user.js` 直链、导入脚本站）；**明文允许只引用仓库链接** | 无附加条款 |
| 对我们是否可用 | ✅ **可用**。我们发 MV3 扩展、不分发它的用户脚本 → 附加条款不适用；仅需保留 MIT 版权声明 | ⚠️ **代码不可抄**，只参考设计思路 |

| 形态 | 用户脚本（Tampermonkey），`version 2.11.5` | 桌面端 PySide6 + **自带 MV3 扩展**（React 19 + Fluent UI v9） |

### 1.1 三项功能的真实实现（这是"直接移植还是优化"的判断依据）

| 功能 | 上游组件 | 真实实现 | 规模 | 依赖上游框架？ |
| --- | --- | --- | --- | --- |
| **删除直播水印** | `live/remove-watermark` | **纯 CSS**，3 个选择器 `display:none !important`；`entry: none`（零 JS） | **5 行** | ❌ 无（`instantStyles` 也不必移植） |
| **删除广告** | `utils/remove-promotions`（**不叫 remove-ads**） | 一张约 **40 项** `display:none!important` 的 CSS 选择器表（用了 `:has()`）+ 少量内联 DOM 换占位 + **把 `.load-more-anchor` 顶到视口外骗提前加载** | ~150 行 SCSS + ~80 行 TS | 部分用了 `spin-query` 轮询、`@/ui` 单选组 |
| **首页净化** | `style/clear-home` | `MutationObserver` 监控 `main > .feed2 > … > .container`，按 `.floor-single-card` 的 `.badge` 文本 / `.bili-live-card` / 含 `.bili-video-card__info--ad` 的卡片 `remove()` | ~60 行有效逻辑 + **37 项分类开关** | 用了 `addComponentListener`（可替代） |

> **推翻了一个常见假设**：「删除直播水印」**不是**改播放器配置或 webcast 接口，就是躲 DOM 元素。
> 推论：**若 B 站把水印烧进画面（视频流内），CSS 方案必然失效** —— 这是必须真机验证的点（§8）。

### 1.2 上游框架能力里，哪些**不可**也不**需要**移植

`defineComponentMetadata` 运行时是**零逻辑**（`return m`）；`instantStyles` 是构建期 scss 打包；
`spin-query` 是轮询等元素；`@/ui` 是 Vue 2 组件。**这四样都属于"上游的壳"，我们一个都不需要**。

**真正必须搬的是"知识"，不是"代码"**：选择器表、`.badge` 文案清单、`load-more-anchor` 这个反直觉的工程技巧。

## 2. UI 重设计（参考 Ghost-Downloader-3，为多功能预留结构）

### 2.1 先说清"参考"的边界

Ghost-Downloader-3 是 **GPL-3.0**。我们同许可证，但**仍不抄源码**。可取的是**设计语言**（思想/表达二分）：

- **Fluent Design / Fluent 2** 的形态：顶部 `TabList`（图标+文字，`transparent`、`small`）+ 右侧独立设置 Tab、第二行状态条、小号 `Switch`（标签在左）。
- **全部走设计令牌，不写字面色值**（它的 `makeStyles` 里只出现 `tokens.colorNeutralBackground2`）。
- **极细描边分割**（`strokeWidthThin`）代替阴影；间距刻度 **6 / 8 / 10 / 12 / 16**。
- 卡片紧凑（高 50–60px）、空状态专门组件、Toast 浮层不打断。

**两条必须记下的限制**：

1. **它的 popup 是 455px 宽、`min-height: 600px`** —— 正好贴在 Chrome MV3 popup 的 **600px 高度上限**上。
   **这个尺寸我们不要照抄**：我们的 popup 现状 360px、已用 422px，加 Tab 后仍有 ~150px 余量。
   建议**宽 380px**，高度靠"净化 Tab 只放 3 项"硬控（§2.3 约束 3）。
2. **它没有可引用的品牌色值** —— 强调色是运行时读系统 `QPalette.Accent` 的，源码里不存在十六进制常量。
   所以**"参考 Ghost-Downloader 的配色"这句话没有落点**；能参考的只有**结构、间距刻度、令牌化做法**。

**技术栈差异（必须说清）**：它是 React 19 + Fluent UI v9；我们是 **Preact + 原生 CSS 变量**。
Fluent 的 `tokens` 是 JS 运行时对象 —— **我们不能引 Fluent UI**（新增依赖 = `AGENTS.md` §7 需先问）。
所以**只借形态，令牌继续用我们自己的 `tokens.css`**。

### 2.2 核心问题：现在的 popup 装不下

现状 `body { width: 360px }`、`.popup { min-height: 220px }`、已用 ~422px，上限 600px。
而 `02-ui-spec.md` §0 的铁律是：**"Popup 是查看器，不是操作台"**，每个元素回答"我现在该担心吗"。

**若把三个新功能开关塞进 popup，铁律立刻破掉**：它们和"有没有生效"无关，是**偏好**。

**所以本次设计的关键不是"加什么"，而是"什么不加进 popup"。**

**具体化这条铁律**：popup 分两类信息，必须物理分开——

| 类别 | 回答 | 落点 |
| --- | --- | --- |
| **状态** | "现在生效了吗" | 默认 Tab（画质），**唯一允许占据首屏的内容** |
| **偏好** | "我让网站变成什么样" | 第二个 Tab（净化）、options |

**三条硬约束（不遵守方案作废）**：

1. **默认停在「画质」Tab**。2 秒法则服务的是"我现在该担心吗"，不能被偏好项抢走首屏。
2. **每项净化开关都要标"当前页适用性"**（灰/亮）。用户在视频页看到「删除直播水印」亮着会困惑——
   **这是 §5.3「不许谎报」原则的延伸**。
3. **净化 Tab 只放最近使用的 3 项**，第 4 项起一律"管理 →"进 options。**popup 不许涨过 600px**。

### 2.3 视觉令牌的增量（`src/design/tokens.css` 唯一真相源）

| 项 | 现值 | 建议 | 理由 |
| --- | --- | --- | --- |
| `--pluma-accent` | `#378ADD` | **不动** | 信息蓝，避开 B站粉（§6 已有明确理由） |
| 圆角 | `12px` / `8px` | **不动** | 与 Fluent 的克制圆角同调 |
| 新增 `--pluma-gap-{1..4}` | 无 | `4/8/12/16px` | 现在间距散落在各 `gap: 7px` 里，多功能后必然不一致 |
| 新增 `--pluma-tab-*` | 无 | 下划线宽 `2px`、tab 高 `32px` | Tab 形态需要一个令牌，不要硬编码 |
| 深色模式 | 已有 | **扩一条**：tab 选中态在深色下用 accent 浅色变体 | 现在深色只换了 accent，tab 高亮对比度未验 |

⚠️ 改 `tokens.css` 会同时影响 **popup / options / login-window / 页内角标** 四处（角标靠 `?raw` 注入 shadow）。
**改完必须在深色模式下各看一眼**，`check-design-imports.mjs` 管不了视觉回归。

### 2.4 options 页：三块 → **四块**

现在 `entrypoints/options/main.tsx` 是 `账号 / 诊断 / 显示` 三块。建议新增「净化」分区：

| 分区 | 内容 | 变化 |
| --- | --- | --- |
| 账号 | 不变 | — |
| **净化**（新） | 三项功能的完整设置 + 未来所有开关 | **新建** `sections/cleaning.tsx` |
| 诊断 | 不变（可加一行"净化规则匹配情况"） | 小改 |
| 显示 | 角标开关 + 深色模式 | 不变 |

> **为什么单开「净化」而不塞进「显示」**：显示分区回答"我怎么看到状态"，净化回答"我让网站变成什么样"。
> 塞一起，下一步再加功能就没地方了 —— 这正是 `02` §4.3 踩过一次的坑（也是当时刻意留白的用意）。

## 3. 功能入口：放哪才"便捷"

### 3.1 popup 新结构（宽 380px）

```text
┌──────────────────────────────────────────┐
│ [●] Pluma        [已接管]      ⚙         │ ← 品牌 + 状态胶囊 + 设置入口
├──────────────────────────────────────────┤
│ 〔画质〕  〔净化〕                         │ ← 两个 Tab（Fluent TabList 形态）
├──────────────────────────────────────────┤
│ tab=画质（默认，唯一"状态"视图）            │
│  当前页解锁画质（02 §2.3 核心区，原样保留）  │
│  双账号卡片 A / B                          │
│  自动接管取流  [开关]                      │
│ ────────────────────────────────          │
│ tab=净化（偏好视图）                        │
│  删除广告        [开关]  (当前页：首页)     │
│  首页净化        [开关]  (当前页：首页)     │
│  删除直播水印    [开关]  (当前页：直播间)   │
│              共 3 项 · 管理 →             │ ← 第 4 项起溢出到此
└──────────────────────────────────────────┘
```

### 3.2 三层入口（按"用户何时会想到它"分层，不追求都放 popup）

| 层 | 位置 | 放什么 | 为什么是这里 |
| --- | --- | --- | --- |
| **1. 场景内即时** | 页内注入小控件（Shadow DOM） | 直播页的水印快捷切换（**可选，第二阶段**） | 用户看直播时才想关水印，此时不该让他点扩展图标（角标已验证这条思路） |
| **2. 一次点击可达** | popup · 净化 Tab | 最近 3 项开关 | 点图标 = 最低成本；但**只放偏好，不放状态** |
| **3. 完整管理** | options · 净化分区 | 全部开关 + 首页分类勾选 + 规则匹配状态 | 复杂 UI 只能在全屏标签页（popup 失焦即销毁） |

**明确不放的地方（与 §3 反模式一致）**：

- ❌ **不进 toolbar badge**（`02` §7：badge 只够 4 字符，只能表达"生效/不生效"）
- ❌ **不做右键菜单**（新增 `contextMenus` 权限 = 扩面，收益不如 popup）
- ~~❌ **不做首页/直播页悬浮球**~~ → **已推翻（2026-11-10，用户拍板）**

  > 原文：「不做首页/直播页悬浮球（遮挡页面，且 `02` §5 明确"不要做任何遮挡播放器的浮层"）」
  >
  > **现在改为做页内入口**，形态是**左侧贴边半隐藏条**（静息 8px，移入展开），
  > 不是常驻悬浮球。位置与层级均有阶段 0 真机实测依据，**完整理由见
  > [ADR 0033](../decisions/0033-panel-first-interface.md)**。
  >
  > 同时废除 options 页、popup 降为「悬浮入口开关」—— 同见 ADR 0033。

## 4. 逐项引入方案

### 4.1 删除直播水印 —— **直接移植（零改动）**

```text
新增 entrypoints/content-live.ts        （独立 content script，matches 只含 live.bilibili.com）
新增 src/content/live/live-clean.css    （选择器表，见下）
```

```css
/* 3 个选择器，与上游逐字一致；保留 !important */
.player-ctnr .web-player-icon-roomStatus,
.live-player-ctnr .web-player-icon-roomStatus,
.bilibili-live-player-video-logo { display: none !important; }
```

**为什么用独立 content 入口，而不并进 `entrypoints/content.ts`**：
`check-page-gate.mjs` 规则 2 要求两个 content 入口的 `matches` **必须同时含** `video/*` 与 `bangumi/play/*`。
并进去 = 让**画质脚本注入到直播间**，凭空扩大画质逻辑的暴露面。**独立入口是唯一不破坏 page-gate 的写法。**

⚠️ 这需要先改 `check-page-gate.mjs` 的 `MANIFEST_MATCHES`（新增第三个入口，但不进 `REQUIRED_MATCH_PATTERNS`）——
**改检查脚本本身属于 `AGENTS.md` §7「改命令入口」，必须先问用户。**

### 4.2 删除广告 —— **优化后再集成**

**不直接移植的理由**：上游 `remove-promotions` 不只是 CSS，它还包含 `spin-query` 轮询、
`@/ui` 单选组、`body` 类名开关、`blocked-ads` 占位 HTML。**其中三样是上游框架的壳**，搬过来只增加维护面。

**移植什么**：

1. ✅ **选择器表**（约 40 项）——这是"知识"，必须原样照抄，逐字。
2. ✅ **`load-more-anchor` 反直觉技巧**——完全隐藏后首页会下半截空白，上游把锚点 `position:fixed; top:-9999px`
   骗页面提前加载。**这段技巧不搬，用户就会看到大面积空白。**
3. ❌ 不搬：轮询、单选组、`debug` 模式、占位文案（我们默认完全隐藏，不给"🚫已屏蔽广告"占位——那是上游的可选项）

**落点**：`src/content/site-clean/` 下的 `ads.ts` + `ads.css`，**作用于 `www.bilibili.com` 首页**。
（⚠️ 本文所有"待新建"路径一律**不加行内链接**：`check-docs` 会把指向未建文件的链接判为死链。）

**风险**：`:has()` 选择器在 Chrome 105+/Edge 105+ 支持，我们下限 120 → ✅ **安全**。

### 4.3 首页净化 —— **优化后再集成，且要削减范围**

**上游实现的问题**：
- **MutationObserver 直接 `remove()` 卡片**：在首页推荐流上删节点，B 站自己的"更多"分页可能算错数。
- **37 个分类开关全部默认 `true`**：等于默认"砍掉 37 类内容"，**用户会认为网站坏了**。
- 容器选择器 `main > .feed2 > .recommended-container_floor-aside > .container` **是硬编码的**，B 站改一次版就整片失效，且**静默失效**（找不到容器就 `return`）。

**我们的优化**（三条，都要写进 ADR）：

| 项 | 上游 | 我们 | 理由 |
| --- | --- | --- | --- |
| 删除方式 | 直接 `remove()` | **用 CSS `display:none` 优先**，JS 只做兜底 | 少改 DOM，降低与 B 站分页逻辑打架的概率 |
| 分类默认值 | 37 项全开 | **默认全关**，用户自己勾 | 默认砍内容 = 让用户以为站坏了 |
| 容器失效 | 静默 `return` | **落诊断日志**（"首页/直播间·样式未匹配"） | 静默失败是本项目踩过三次的最大帮凶 |

### 4.4 共用底座（三项都要，且必须**共用一份**）

```text
src/content/site-clean/
  registry.ts   ← 功能清单：id / 名称 / 适用站点 / 选择器常量 / 默认值
  style.ts      ← 往 document.head 插 <style>，带 !important；开关变化时增删
  index.ts      ← 统一入口
```

**⚠️ 绝不能用 Shadow DOM。** `AGENTS.md` §5.3 说"页内注入必须 Shadow DOM"——那条的上下文是**我们自己的 UI**（角标）。
隐藏 B 站元素的样式**必须作用于文档树**，塞进 shadow root 会**完全命不中**。
**这是本方案的第一个技术陷阱，必须写进 ADR，否则下一个人会照着 §5.3 做错。**

## 5. 直接移植 vs 优化后集成（汇总判断）

| 功能 | 结论 | 理由（一句话） |
| --- | --- | --- |
| 删除直播水印 | **直接移植** | 5 行 CSS，零逻辑、零依赖，改写只会引入分歧 |
| 删除广告 | **优化后集成** | 核心选择器表直接抄；但**只取选择器与 preload 技巧**，丢掉上游 UI 框架壳 |
| 首页净化 | **优化后集成 + 削减范围** | 上游逻辑可用但默认值激进、容器硬编码且静默失败，必须按本项目原则重做默认与错误处理 |

**统一的判断尺度**（建议写进 ADR，供以后所有"引入上游功能"复用）：

> **搬"知识"（选择器、文案清单、工程技巧），不搬"壳"（框架、轮询、UI 组件、构建期魔法）。**
> 判据：这段代码离开上游框架还能独立讲清"为什么必须这样"吗？能 → 搬；不能 → 重写。

### 5.1 许可证与署名（`NOTICE` 新增）

Bilibili-Evolved 是 **MIT**：必须保留版权与许可原文。建议新增 **`NOTICE`**（或 `THIRD-PARTY-NOTICES.md`）：

- 列出 `remove-watermark.scss` / `remove-promotions.scss` / `clear-home/index.ts` 三项的来源与 MIT 声明
- 明确"**未使用** Bilibili-Evolved 的运行时框架代码"
- `clear-home` 上游作者是 `RieN7`，**单独署名**

这同时要改 `README.md` 的「致谢」节（现在写的是"均未使用其源代码"，**将不再成立**，必须改）。

### 5.2 一个必须承认的维护风险

三项功能**全部依赖 B 站当前 DOM 结构**，而画质功能依赖的是**接口**（相对稳定）。
后果：**B 站一次改版就可能让净化全灭**，且**不会报错**。

建议（进 ADR）：在诊断页加一行「净化规则匹配情况：首页 ✓ / 直播间 ✗」，让失效**可见**。
这也解释了为什么 §4.4 必须共用 `registry.ts`：**失效要能一次查完**。

## 8. 实施顺序与验收（含反例）

```text
M0 决策闸  → ADR 0031（边界+权限）/ ADR 0032（Slogan）→ 用户批准    ← 不批不动手
M1 权限    → host_permissions + 新 content 入口 + page-gate 放行 → verify 绿
M2 水印    → content-live.ts + live-clean.css（5 行）           → 真机：直播页水印消失
M3 广告    → site-clean/ads.{ts,css} + preload 技巧             → 真机：首页无广告且不空白
M4 净化    → site-clean/ + 默认全关 + 诊断日志                  → 真机：勾选后卡片消失、未勾选不变
M5 UI      → tokens 增量 → popup Tab → options「净化」分区      → 深色/浅色各一遍
M6 文案    → 6 处副标题 + manifest + README 致谢                → verify --fast 绿
```

### 8.1 每项的反例验证（"修好了"必须能变红）

| 功能 | 把什么改回去 | 期望 |
| --- | --- | --- |
| 水印 | 删掉 `display:none` | 水印**必须重新出现**（若删了也不出现 → 说明**水印烧进画面**，CSS 无效，见 Q18） |
| 广告 | 把 `load-more-anchor` 技巧去掉 | 首页**必须出现空白**（证明这个技巧是必需的，不是装饰） |
| 净化 | 把默认值从"全关"改成"全开" | 首次进入首页**必须看到卡片大面积消失**（证明默认值选择是有意义的） |
| 净化 | 把容器选择器改错 | 诊断页**必须报"样式未匹配"**（证明不是静默失败） |
| 权限 | 去掉 `live.bilibili.com` | 直播页**必须完全不注入**（证明 §0.1 的判断成立） |

### 8.2 无法自动化、必须人肉的部分

- 4K/水印的**肉眼对比**（`00-handoff` §9 已列为"自动化不可靠"）
- **B 站改版导致选择器失效**——只能靠诊断页的匹配状态行暴露
- **深色模式视觉回归**

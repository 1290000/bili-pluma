## 2. R1 可复现性实测（原 `1.1.0-plan.md` §2.5）

> ⚠️ **本节被 [ADR 0030](../decisions/0030-pgc-reload-guard-semantics.md) 引用**（「G3 行与 R1」），结论不得改动。

- 方法：整仓复制到 `.tmp/r1/repo`（`node_modules` 用 junction，排除 `.output`/`dist`），副本内 `wxt build`
- **同 commit、Node 24.21.0 两次 build**：`chrome-mv3` **24 个文件 sha256 逐字节一致**
- **Node 22.22.2 vs 24.21.0**：**24 个文件逐字节一致**
- 结论：BUILD.md 的逐文件哈希方案可行；凭证必须记录 Node 版本、wxt 版本（0.21.4）、`pnpm-lock.yaml` 哈希
- 边界：单机 / Windows x64；跨机器、跨 wxt 版本未测。比对对象是 `extension/**` 逐文件，不是 zip 字节（zip 含时间戳）

## 4. Slogan 决策（原 `1.1.0-multitool-plan.md` §6）

**2026-10-31 的结论**：换副标题、不换主名 → 采用 **「B站双账号助手 · 画质与净化」**。当时的候选表：

上表 ④「B站多功能助手」当时被判"不推荐"，其理由（无记忆点）**未被推翻**，只是最终没采用这条路线。

## 7. 边界与门禁（原 `1.1.0-plan.md` §2.2 / §2.3）

> ⚠️ 这两条是**规则级**约束，不随版本过期。

**Out of scope（1.1.0 明确不做）**：

- 新功能、v1.5 项、`main-world.js` 重构、超出双账号的能力
- **任何新增改写路径/主机**（AGENTS.md §5.5：先改 ADR 再改代码）

**发布门禁**：

`verify` 全绿；改 `dnr.ts` 则跑两个 DNR 脚本；改 `main-world.js` 则要真机日志；每个修复附"改回去必须红"的反例。

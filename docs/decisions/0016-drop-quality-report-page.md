# ADR 0016. 砍掉画质体检表与音质自检独立页

日期：2026-10-26
状态：已采纳
影响：[02-ui-spec.md](../02-ui-spec.md) §2.6 / §4、[01-architecture.md](../01-architecture.md) §9 验收、
`entrypoints/options/`、`src/platform/http/playurl.ts`

## 背景

P3 的原计划里，options 有五块，其中两块是：

1. **画质体检表**（§4.2），规范称它是"核心卖点页"，README 首屏用它截图
2. **音质与环境自检**（§4.3）

写完 popup §2.3 之后回头看，这两块的性价比都不成立。

## 决策

**砍掉画质体检表；音质自检降级为「诊断」分区里的一个折叠块；options 从五分区降到三分区
（账号 / 诊断 / 显示）。popup 底部同步从三按钮改为两按钮。**

## 理由

### 体检表与 popup §2.3 是同一份数据

| | §2.3（已实现） | 体检表 |
| --- | --- | --- |
| 数据源 | 当前页的 `dash` 轨道 | 同一份 |
| 对比结论 | `主账号仅可用 1080P` | 同一句，做成表格 |
| 多出来的 | — | 杜比视界 / 杜比全景声两行 |

而 [ADR 0014](./0014-quality-compare-from-page-data.md) 已经把它锁死在"**只能看当前页**"——
用户点进体检页，看到的就是他刚才在 popup 里已经看过的结论，只是换了排版。

### 成本远大于收益

要做体检表得先付三笔：

1. **Q9 校准**（`fnval` 实测）：`playurlQuery` 里的 `4048` 是推算值，不校准就会得出
   "播放账号也不支持 Hi-Res"这类错误结论
2. **`playinfo/get` 的 handler**：消息类型有了，处理方一直没写
   （2026-10-27 补记：该类型已随本决策落地而删除 —— 既然不做体检表，它永远不会被实现）
3. **一整页 + "当前页限定"的边界处理**

### 音质自检测不准

Q14 的结论本来就是"可能测不准，退化成检查清单"。而"检查清单"是**静态文字** ——
为静态文字开一整页，用户点进去只会觉得空。真能测的只有
`new Audio().canPlayType('audio/flac')` 一行。

### 空壳页会传递错误信号

五分区里有三个是"本页尚未实现"的占位清单。用户点进设置看到这个，比没有这些页更伤 ——
它说的是"这软件没做完"。

## 被放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 保留体检表，但不做 Q9（直接用页面的 `fnval` 数据） | 那等于"用同一份数据再排一次版"，与 §2.3 重复；仍然要为它写 handler 和边界处理 |
| 保留体检表，只做当前页 | 那就是 §2.3 的放大版，收益只剩"杜比两行" |
| 音质自检保留为独立页 | 静态清单不值得一个导航项；放进诊断页的 `<details>` 即可 |

## 后果

- **删掉死代码**：`platform/http/playurl.ts` 里的 `fetchPlayurlAsPlayback` / `playurlQuery` /
  WBI 密钥缓存全部删除，只留 `buildCookieHeader` / `deviceCookiesFrom`。
  那条路径的 `fnval=4048` 从未实测，留着就是"哪天有人调它，结论就错"的雷。
- **Q9 不再阻塞任何东西**：我们不再自己发 playurl，页面的请求用的是 B站 自己的 `fnval`，
  天然正确。`03-open-questions.md` 的 Q9 保留为"未实测"记录，但不再是 P3 的前置。
- **README 少一张对比表截图**：改用 popup §2.3 的截图替代 —— 它更真实
  （出现在用户真实使用时，不是专门跑出来的）。
- **`core/wbi/signer.ts` 失去生产调用方**（只剩单测）。暂时保留：它是纯逻辑、
  将来若真做体检表（v1.5）还要用；但**再也没人调用就该删**。
- **验收标准要改**：`01` §9 的六条里有两条指向体检表与音质自检，已改写。

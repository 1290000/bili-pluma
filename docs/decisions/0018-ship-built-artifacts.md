# 0018. 分发构建产物（放宽「只发源码」红线）

日期：2026-10-27
状态：已采纳（**对决策 8「只发源码，不发预编译包」的修订**）

## 背景

v1 六条验收通过后，用户提出：希望用户能**直接下载扩展包并加载**，而不是每个人都得装 Node、跑 `pnpm build`。

这条诉求与决策 8 直接冲突。决策 8 原文：

> **只发源码**，不上架商店、不发预编译包

理由是（见 [Q16](../03-open-questions.md) 与 [Q13](../03-open-questions.md) 背景表）降低「提供可用侵权工具」的观感，减小暴露面。

**用户决定要做。** 本 ADR 记录「怎么做才把代价压到最低」，不再讨论「要不要做」。

## 决策

改为：**不上架商店；不发 crx；可以发 zip，但 zip 必须同时提供带源码的版本。**

精确边界：

```
允许发布：  pluma-<版本>.zip              构建产物，解压后可在开发者模式加载
            pluma-<版本>-with-source.zip  同上 + 完整源码（可复现构建）
禁止发布：  crx（任何来源自签的一律装不上，且观感是"已签名安装包"）
            任何形式的网盘 / 第三方镜像主动分发
            上架 Chrome / Edge 商店
必须保持：  README 以**源码构建**为主路径，zip 是退路而非主推
```

权威位置分工：

| 内容 | 权威位置 |
| --- | --- |
| 为什么这样分发、边界在哪 | 本 ADR |
| 文件名格式、zip 内结构、发布步骤 | [guides/releasing.md](../guides/releasing.md) |
| Release 说明的语气与结构 | [guides/release-notes-template.md](../guides/release-notes-template.md) |

## 为什么保留「必须同时发带源码版」

这一条是本次修订的**核心约束**，不是补充说明。

只有「构建产物」时，它在用户眼里就是一堆 js —— 和任何一个来路不明的扩展没有区别。加上源码，能让第三方**独立重建并比对**。区别不在体积（216 KB → 约 1 MB），在于**可验证性**。

⚠️ **诚实说明它的局限**：带源码**不能**让产物变合规或更安全。它只是让「这是在做什么」对任何人可见。**不要把它当免责手段用** —— 它是自我约束，也是证据。

## 为什么明确禁止 crx

技术上就装不上：浏览器只认商店签名的 crx，自己生成的会被拒绝安装。既然装不上，发出去只会制造「下载了不能用」的投诉，还平白留下「我发了安装包」的痕迹。

## 被放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 只发源码（维持原决策） | 用户明确要求降低使用门槛；且参考实现里也有直接给产物的做法 |
| 发 crx | 浏览器拒绝非商店签名，用户装不上 |
| 发 exe 安装包 | 要写注册表 + 改浏览器策略，会被杀软报毒。**观感比发 zip 恶劣得多** |
| 让用户把 zip 直接拖进浏览器 | 浏览器没有这个入口。「加载解压缩的扩展」只接受**目录** |

## 后果

- `AGENTS.md` 决策 8 改为「不上架商店；分发方式见本 ADR」—— 决策表只留指针，细节归这里
- `docs/03-open-questions.md` Q16 的「分发决策」表同步改写
- `README.md` 安装章节重排：**源码构建（推荐）在前，zip 在后**
- 新增 `scripts/package.mjs`，命名与结构由 `releasing.md` 定义
- Release 说明必须包含「未经商店签名，仅供学习交流」这句

## 没有改变的事

| 项 | 状态 |
| --- | --- |
| 不上架商店 | **不变** |
| 不做中文 SEO / 不主动推广 | **不变** |
| 不提供绕过付费墙的能力 | **不变**（这是能否站住的分界线，与分发方式无关） |
| 收到律师函的预案 | **不变**，见 [Q16](../03-open-questions.md) |
| 许可证 | **不变**，GPL-3.0-only + 附加条款 |

发 zip 会让暴露面略增，但**不改变这个项目「可能随时停止维护」的判断**。

# Pluma

> **B站双账号画质助手**
>
> 用主账号浏览、点赞、收藏、评论，让一个大会员账号专门负责播放。

GPL-3.0-only · Chrome 120+ / Edge · **v0.9.0（2026-10-26）**：v1 范围已完整落地并通过六条验收

## 它做什么

浏览器里有两个身份，职责完全分开：

| 身份 | 存在形式 | 负责 |
| --- | --- | --- |
| **主账号** | 浏览器自己的登录态，扩展不碰 | 收藏 · 点赞 · 评论 · 投币 · 播放历史 |
| **播放账号**（大会员） | 扩展加密存储的凭据 | 仅提供取流，解锁 4K / 1080P60 / HDR / 杜比 / Hi-Res |

原理是**请求级身份代理**：浏览器全程保持主账号登录，扩展只在白名单取流接口上换一套凭据重发。**不切 cookie、不写 cookie jar、主账号会话从头到尾没被动过。**

所以点赞记在主账号、历史记在主账号、评论是主账号发的——但视频流按播放账号的权限拉。

## 它不做什么

- ❌ 不绕过付费墙（会员专享番剧/电影仍需购买）
- ❌ 不伪装会员标识（界面如实显示真实状态）
- ⚠️ 会改写**播放器自己**用于判断会员状态的接口响应，只为让画质切换不被拦截；**不改变账号在服务端的真实权益**（[ADR 0013](./docs/decisions/0013-patch-player-info-response.md)）
- ❌ 不解锁地区限制
- ❌ 不共享账号
- ❌ 不提供任何破解或加密绕过手段

## 凭据如何存储

播放账号凭据以 **AES-GCM** 加密后存在本地，密钥同样保存在本地。**这个加密能防什么、不能防什么，说清楚：**

- ✅ 能防：其他网页脚本、其他扩展直接读到明文
- ❌ **不能防本机程序**——能读本机文件的程序可以同时拿到密文和密钥
- ❌ 也不改变：B站登录态本身就以 cookie 存在浏览器里，本扩展的加密不涉及那部分

不上传凭据到任何服务器。没有做"口令解锁"——它防不住上面第 2 条，只会增加负担（[ADR 0009](./docs/decisions/0009-drop-passphrase-mode.md)）。`cookies` 权限**只在扫码登录播放账号那一刻读一次**，不读主账号、不读其他网站（[ADR 0008](./docs/decisions/0008-cookies-permission-for-playback-credential.md)）。

## 音质需要你的环境配合

**Hi-Res** 通常开箱可用（Chrome/Edge 原生 FLAC 解码）。**杜比全景声**需三件事同时成立：装 Microsoft EC-3 解码扩展（Store ID `9nvjqjbdkn97`）· 浏览器启用 media foundation playback · 系统音频设为空间音频/E-AC-3 直通。扩展**不做任何解码**，设置页的「音质环境」折叠块会报解码器在不在，链路仍需你自己核。

## 安装

**不上架任何商店，也不提供预编译安装包**，请自行构建：

```bash
pnpm install && pnpm build
```

`packageManager` 锁在 `pnpm@12`，换 npm/yarn 会与 `pnpm-lock.yaml` 不一致；没装就 `npm i -g pnpm@12`。

然后 `chrome://extensions/` 或 `edge://extensions/` → 开「开发者模式」→「加载已解压的扩展程序」→ 选 **`.output/chrome-mv3`**（**不是**仓库根目录，`manifest.json` 是构建产物，理由见 [releasing.md](./docs/guides/releasing.md)）。
